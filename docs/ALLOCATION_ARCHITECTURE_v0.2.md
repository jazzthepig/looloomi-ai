## 0. 要回答的问题(Jazz,09-29)

1. **实时评估**每个资产、每个策略在它**当前所处状态**下的风险收益比。
2. 把评估**映射成仓位**:什么时候加风险、什么时候收缩、什么时候可以做空。
3. **挖掘周期性机会。**
4. 形成**可执行的交易链路**。
5. **全部留在库里**,多个组合之间比较,不急着定性;新架构是加法,不覆盖旧的。

v0.1 的诊断是对的(见附录 A),但它没有给出任何一个可以计算的量。v0.2 的规矩:**每个概念都写出它是哪张表、哪个函数、怎么验收。**

## 1. 五条原则

| # | 原则 | 反面是什么 |
|---|---|---|
| P1 | **连续,不是二值。** 仓位、敞口、策略权重都是随证据连续变化的数;「上线/归档」「多/空」只是连续值的两个端点 | `decide()` 只输出 ENTERED / SKIPPED / BLOCKED;信号只有 ±1、每次满仓 |
| P2 | **库只增不删。** 每个策略永久登记,权重可以降到 0,记录永远在 | 「这个错了,删掉」 |
| P3 | **一套记账内核。** 所有策略——研究、回测、前向——都通过同一个函数从「目标权重」算到「逐日 NAV」 | S-437:ETH 多空回测持仓数周却只记前 5 天盈亏 |
| P4 | **时间戳语义写死。** `trade_date` = 这根 bar 覆盖的那一天;`recorded_at` = 最后一次值变化;一律 UTC | S-436:CoinGecko 蜡烛戳是收盘时刻,整张表晚了一天 |
| P5 | **层级是先验,不是菜单。** ① 持有面板是默认;证据不足时配置自动回到 ①;④ 在有前向记录之前有权重上限 | 在 +41% 的趋势里满仓做空 |

### L0 数据 —— 真实、对齐

### L1 状态估计 —— 输出概率,不是标签

每天、每个标的、以及整个市场,算一个状态向量 `s_t`。**只用 t 及以前的数据。**

| 维度 | 例子 | 已有 |
|---|---|---|
| 趋势 | 相对 50/200 日线的位置、距 52 周高点、14/28/90 日动量 | 部分(`beta_plus_momentum.combo_signal`) |
| 波动 | 已实现波动率的历史分位 | 部分 |
| 宏观 | regime 的**概率**(不是四选一) | 有四选一标签,要改成概率 |
| 广度 | 面板里站上 200 日线的比例 | 部分(R11/R12) |
| 反身性 | 资金费率极值、持仓量变化、清算、阶梯式上涨/下跌的形态计数 | 资金费率、OI 已入库(T-012) |
| 周期 | 星期、月份、资金费率结算周期、代币解锁日历、宏观日历 | 无 |

**风格表头(T-039,L1 的第一件事):** 每个标的在每一天属于哪个风格 —— 大币 / 头部公链 / 二线公链与 L2 / DeFi / 基础设施与代币化 / AI / meme —— 以及它在当天的市值档位(PIT)。在此之上每天算各风格的指数(市值加权与等权两版),以及每本账本对各风格的暴露。**风格周期判断(HIGH_DIM §5b-bis ⓪、DECISION_PATH_SPEC ①)一直是设计的第一步,但没有这张表头,系统就分辨不了「现在是大币周期还是山寨周期」,也说不出任何一本账本在各风格上暴露多少。**实测:2023-12 → 2026-09 BTC +92%、24 名面板等权 −7.5%;09-05 → 09-28 反过来山寨普涨、BTC +6% —— 收益主要由风格轮动决定。

**新表** `state_daily(d, entity, feature, value, source, code_ref)`,长表格式,加一个特征不改表结构。
评估时才把连续值切成格子(见下),格子数量要克制:**每个维度 ≤ 3 档,同时用的维度 ≤ 2 个**,否则每格样本太少。

### L2 策略库 —— 只增不删,统一记账

- **新表** `strategy_registry(id, layer ①–④, cause, params_hash, code_ref, added, status)`。
  `status` ∈ {research, paper, live, dormant};**没有 deleted**。登记要求 `cause` 非空(TRADER_TOM_DOCTRINE)。
- **一个记账内核** `nav_kernel(target_weights, prices, cost_bps, lag=1) → daily NAV`:
  权重随价漂移、下一根成交、按换手扣成本、逐日记账。
  `beta_plus_momentum._simulate` 已经是这个形状,把它提出来成为公用内核;**其他地方不许自己写记账。**
- 每个策略每天产出:目标权重 + 由内核算出的 NAV(研究回放与前向账本用同一内核 —— S-431 已经证明可以逐位复现)。
- 现有的逐日账本全部登记进来,不改它们:`beta_core_nav` ①、`beta_plus_daily` ②-MOM、`tokenization_tilt_daily` ②-TOK、`hl_book_daily`、`fusion_paper_nav`、`combined_book_nav`、`causal_paper_nav`、`dingge_paper_nav`、`scalable_book_nav`。

### 评估 —— 风险收益矩阵(这是 Jazz 第 1、5 条的直接答案)

行 = 策略,列 = 状态格子,**每一格是一个分布,不是一个数**:

| 字段 | 定义 |
|---|---|
| `n_days` | 这一格里有多少天 |
| `excess_mean` / `ci_lo` / `ci_hi` | 相对「持有同一面板」的日超额,年化;块 bootstrap(块长 20 天)95% 区间 |
| `p_pos` | bootstrap 里超额 > 0 的比例 |
| `beta` | 对面板的 β |
| `rel_maxdd` | 相对净值的最大回撤 |
| `turnover` | 年化换手 |
| `n_variants_tried` | 这个策略家族一共试过多少变体(用于 deflated Sharpe,防止挑出来的最好一格) |

- **小样本收缩:** 格子里天数少时,估计值向该策略的全样本值收缩(经验贝叶斯),而不是直接信那一格。
- **新表** `rr_matrix_daily(d, strategy_id, cell, …)`:每天重算,历史保留 —— 可以看到每一格的判断随时间怎么变(v0.1 说的「退相干速度」就是这里的斜率)。
- 策略之间:按状态分段的超额收益相关矩阵,同表旁挂。

### L3 配置 —— 连续,受层级约束(这是 Jazz 第 2 条)

在当前状态 `s_t` 下,每个策略有后验期望超额 μᵢ 和不确定度 σᵢ(来自评估层)。

1. **策略权重** ∝ max(0, μᵢ) / σᵢ²,再乘一个分数凯利系数(先定 0.25)。**单策略上限 80%,单一标的(合并所有策略后的净持仓)上限 40%**(Jazz 09-29)。证据越弱,权重越小 —— 这就是「不是二值」。
2. **总敞口** eₜ ∈ [−0.3, 1.3](⓪ 的范围):默认 1.0(① 持有面板);只有当「趋势 + 宏观 + 反身性」三类状态的后验同时指向同一方向、且对应的择时策略在该格子里 `ci_lo > 0` 时才偏离 1.0,偏离幅度与证据强度成正比。**做空只是 eₜ < 0 这一端,不是单独的开关;任何时候都可以,条件是特征成立且风险调整后收益足够高(Jazz 09-29)** —— 操作上即:对应格子的风险调整超额 `ci_lo > 0`,且其年化超额 / 波动 ≥ 与做多同一门槛。
3. **层级约束:** ④ 在前向记录不足 60 天时,合计权重上限 10%;③ 的择时只能调 eₜ,不能自己开多空。
4. **人工通道(⓪):** Jazz 可以下一个带理由的偏置,记入 `allocation_override(d, delta, reason, horizon, expires, by)`;配置结果里显示它贡献了多少。每次下偏置时选有效期,四选一:**7 天 / 14 天 / 1 个月 / 全委托**。前三档到期自动失效、可续期;**全委托** = 不设人工偏置,敞口完全交给 L3 按证据决定(这也是没有下偏置时的默认状态)。
5. 输出 **新表** `allocation_daily(d, strategy_id, weight, exposure, why)`,`why` 写清是哪几格证据驱动的。

### L4 执行链路 —— 目标到归因的闭环(Jazz 第 4 条)

```
allocation_daily → 目标持仓(标的层面) → 下单(先纸面) → 成交 → 持仓 → nav_kernel 逐日 NAV
      → 归因(按策略、按状态格子、按层级) → 回写评估层
```

- 幂等、UTC、每一步有自己的判活判据(Rule 5b)。
- 纸面阶段:成交价 = 下一根收盘 + 成本模型;S-432 的结论照用:加仓下一根收盘成交,减仓立即。
- 实盘接入是后面的事;链路先在纸面上跑满 60 天。

## 4. 周期性机会放在哪

- **识别**在 L1(周期特征是状态的一部分)。
- **利用**在 L2(一个策略专门在某个周期相位加仓,就是一行新策略)。
- **判断**在评估层(它在对应格子里有没有 `ci_lo > 0`,且在不同年份里同号)。
- 每一个周期假设先写进台账(假设、格子、判据),再跑 —— 与 M-189 的预注册同一个规矩。
- 已知的警示:S-431 的「星期几运气」(同一信号只因调仓日不同就差 5.6 个点)。周期发现首先要排除的就是这种。

## 5. 组合之间怎么比

比较的对象是**配置政策**,不只是策略:

| 政策 | 内容 |
|---|---|
| P0 | ① 持有面板(基准) |
| P1 | 现行固定倾斜(②-MOM + ②-TOK) |
| P2 | L3 的状态条件连续配置,不含人工通道 |
| P3 | P2 + 人工通道 |

- 同一内核、同一数据、同一成本;报告先写总收益 vs P0,再写超额,再按状态分段。
- 历史回放给先验,**前向 60 天定结论**;任何一个政策都不因一次回放被删。

## 8. 风险与不做的事

- **格子太多就是在挖数据。** 维度与档数有上限(L1),`n_variants_tried` 进 deflated Sharpe。
- **状态必须 PIT。** regime 标签、周期特征都只能用 t 及以前 —— 有专门的测试。
- **不在内部代码和对外材料里用物理术语。** 名字就是它是什么:状态、分布、权重。
- **对外一律合规措辞**(OUTPERFORM / UNDERWEIGHT 等),本文件是内部设计。
