## 5. 复算用的规则(全部照台账,没有放松)

- 事件 = `events` kind=perp_listing、source=binance,共 **818 条**(分页带 `order=`,核过 Content-Range 总数)
- 上线日 d = 标题里的日期(YYYY-MM-DD),没有则事件 ts 的 UTC 日
- 现货先行条件 = 上线日之前 ≥ 60 根 `binance_hist` 日线,且首根到 d 的日历跨度 ≥ 60 天
- 价 = `binance_hist` 现货**收盘**;超额 = ln(P_{d+30}/P_d) − ln(P_BTC,d+30 / P_BTC,d);BTC 同源(`binance_hist` 的 BTC,3,369 根)
- 零信号对照 = `apparatus.random_dates_like`(同代币、同年份随机日)1,000 次、种子 740 → `null_distribution` → `percentile_of`
- (d) = 去掉「上线前 30 天涨幅 > 50%」的那批(用 d−30 当天收盘做基准)
- 读法扫描:映射(标题 / `events.symbols` / 并集)× 公告类型(3)× 保证金(5)× 上线日(标题 / ts)× 取价(当天 / 3 天内首个有价)× 现货 60 天口径(3)× 去重(3)= **2,160 组读法**,n 落在 86–148,其中 **192 组**同时满足 |Δn| ≤ 7 且 |Δ中位| ≤ 1.5pp —— 主口径 B 是其中 n 与中位同时最接近台账的一组(Δn=+1,Δ中位=+0.98pp)

## 6. 没做的部分(还差什么)

- **按上线前市值三分位的副项**(台账 −22.7 / −21.1 / −14.0)没有复算:需要代币 → `asset_mcap_daily` 的映射与「上线前市值」口径,本轮没做,不报数。
- **上线后 7 天资金费与超额的相关**(台账 Spearman +0.35)没有复算:需要 `funding_history` 的 binance_perp 逐期序列与事件对齐,本轮没做,不报数。
- 季度/交割合约与「杠杆档位调整」类公告在两个读法里都排除了(它们不是「上线日」);若台账口径把它们算进去了,那 n 会再高一截,台账文字里看不出这个意思。
