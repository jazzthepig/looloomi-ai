## 2. 筛选:自己写的「整币下架」规则(先筛、后取价)

台账写死的是「只取整个代币下架(标题是 "Will Delist <代币>…" 一类),把『移除某些交易对』『仅杠杆/仅合约』排除」。
我据此自己写了一条正则(写在看价格之前):

```
纳入 = ^Binance (Announced the First Batch of Vote to Delist Results and )?Will Delist <币名列表> on <YYYY-MM-DD>$
排除 = ① 只针对保证金 / 借贷 / 抵押品 / 期权 / 杠杆代币 / 质押 / Alpha / Earn 的公告(币仍在现货)
       ② 「移除交易对」类公告(标题不带币名 ⇒ 无从知道哪些币;带币名的也是移除交易对,不是整币下架)
```

对全部 368 条标题跑一遍,逐条理由落在 `t287_screening.json`(每条含 id / ts / title / reason / tokens):

| 理由 | 条数 |
|---|---|
| **included(整币下架)** | **39** |
| excluded_pair_removal(移除交易对) | 193 |
| excluded_margin_or_loan(保证金/借贷/可借资产/抵押品) | 109 |
| excluded_alpha(Binance Alpha) | 11 |
| excluded_other(币价变更 / 重新命名 / 质押赎回等) | 6 |
| excluded_leveraged_token(UP/DOWN 杠杆代币) | 5 |
| excluded_earn / excluded_options / excluded_staking_only | 2 / 2 / 1 |
| **合计** | **368** |

从 39 条标题里抽币名(逗号 / `and` / `&` 分隔,只留全大写字母数字):**164 个,零重复**
⇒ 164 个代币各对应一次公告,「一个代币多次公告取第一次」这条预注册自动满足。

> 台账说排除 329 条、其中 188 条是「移除现货交易对、标题不带币名」。我的 193 条 pair_removal 里有 186 条
> 是标题纯为 `Notice of Removal of (Trading|Spot Trading) Pairs - <日期>` 这种不带币名的,其余 5 条带币名
> (如 `Notice of Removal of AXS/BIDR Trading Pair`)仍按「移除交易对」排除 —— 理由不同,总数同量级。

| 对照 | 同一代币在 `[d0−365, d0−60]` 里随机取日子(该代币在这段要有合格日:日价与 +30 天价都存在)⇒ 200 次抽样,每次算一遍 53 个代币的 30 天超额**中位**;事件中位在这个「对照中位分布」里的分位 = `percentile_of`。 |
| 统计 | 全部用 `src/data/evaluation/apparatus.py`:`long_return` / `price_on_or_after` / `random_dates_like` / `null_distribution` / `percentile_of`。零分布种子 `20261107`,n = 200。 |

## 5. 副项与探索性(不判)

- **7 天超额中位 −13.647%**(主口径 30 天 −37.7%)。也就是说:公告之后的下跌,**头 7 天就走了约三分之一**,后面继续。
- **公告前 30 天 −34.396%、公告当天 −23.733%** ⇒ 头寸在公告**之前**已经在流血,公告后再跌 37.7%。
  这跟台账的读法一致(Jazz 不接受「坏币的持续性」那句,但数没变)。
- **按公告前市值三分位**(mcap 取 d0 当日 `asset_mcap_daily.mcap`):
  小市值 n=16 中位 **−78.77%** · 中市值 n=16 中位 **−29.89%** · 大市值 n=18 中位 **−21.55%**。
  效应**集中在小市值**(最大的一档比最小的一档差约 57pp)。
- **可见性缺口**:164 个代币里 **111 个(67.7%)在 `asset_mcap_daily` 里根本没有行情** —— 不是「跌得看不见」,
  是这个宇宙压根不覆盖它们。台账读「效应是下界」成立;**更准确的说法是:可见的 53 个本来就是能活到被跟踪的那批,
  看不见的 111 个里绝大多数是已经死透的币**。
- **交叉源**(ohlcv_daily, source = `coingecko_pro_ohlc`,台账点名的那个源):32 个可算(该源的 BTC 只覆盖
  2025-08-26 → 2026-11-06,所以只有 2025–26 的事件可算),中位 −55.0%、84.4% 为负 ⇒ 与主口径同向、更极端。

**探索性 —— 需另立预注册、在新数据上过零信号对照:**
1. 「小市值那段更狠(−78.8% vs −21.6%)」是单样本切分,没做对照检验,不能当机制用。
2. 「7 天走完三分之一、公告前已经在跌」⇒ 可能真正的可交易窗口在公告**前**(S-754 / S-753 那两条线),不在公告后;
   本卡不判这一条。
3. 「111 个看不见」这个缺口本身可能是可测的(覆盖率与后续收益的关系),需要另立预注册。

## 6. 差异在哪一步(万一以后要查)

本次**没有**对不上的地方(逐项差都 ≤0.73pp)。唯一可能产生微小差的是两处**实现选择**(两边都是合理选择):
