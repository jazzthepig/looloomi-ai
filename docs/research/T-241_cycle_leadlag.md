**为什么没有候选**(逐条说清楚,这是本卡的主要结论):

1. **先行天数这一条几乎全军覆没**:三段崩塌里,各分量的不良方向穿越绝大多数发生在峰前 100–330 天,而不是 −90…0 天窗口里。峰前 90 天窗口内唯一稳定出现的穿越是 `mom_60` 的 Δ30 形态(见下),但它的池化收益分位只有 0.51–0.83,不够 0.95。
2. **分位够高的那几行,信号是日历代理**:水平形态(`z`)的顶/底档平均日历日相差 365–808 天(见表 C),五分位在趋势型序列上≈按日历切段,于是 Δ 量的是『样本里哪一段牛/熊』,不是可交易的关系。块置换零分布抓不到这个混淆(它破坏的是信号与结果的**对齐**,不是信号本身的**趋势**)。
3. **两行同时满足『三期限同号 + 90 天分位 ≥ 0.95』,但都不是崩塌预警**:`taker_buy` 的 Δ30 形态(0.97 / 0.987 / 0.958)方向是**顶档回报更高**(+8.1 / +16.2 / +16.2pp)—— 风险**确认**,不是前兆;`stable_supply_30d` 的 z(0.99 / 0.995 / 0.988)日历差 +808 天 —— 纯日历代理。两行的先行天数都是 0 段(`taker_buy` 的 Δ30 只在 2025-10 段有 1 次穿越,在峰前 290 天,0 次落在 −90…0 窗口内)。

## 5. ⑤ 诚实

- **54 次比较**(9 分量 × 2 形态 × 3 期限)。若分位均匀,α=0.05 下期望有 ≈2.7 行『假阳性』;本卡最高分位那一行(0.995)在 54 次里并不稀奇。候选要进 ⓪ v3 的预注册才判,本卡不判。
- **日历混淆没有解决**,只是被量出来了(表 C 的『日历差』列)。水平形态的强分位基本都可以用『这一行是某一段行情的代理』解释掉(差 365–808 天);Δ30 形态里日历差小的(`taker_buy` −38、`breadth` +34、`mom_60` +50、`funding` −79 天)分位也低,只有 `taker_buy` 的 Δ30 例外(0.97 / 0.987 / 0.958)—— 它的日历差只有 −38 天,所以这一行是全表里**最不像日历代理**的强结果(但它是『涨得好』,不是『要崩』)。
- **零分布口径**:主口径(置换信号)与副口径(置换结果)的分位方向与量级一致(逐行对照见 `t241_results.json` 的 `null_pct_outcome_perm`),所以结论不依赖选哪一版。
- **`lend_apy` / `oi_chg`**:数据不够(`lend_apy` 的 z 从 2024-02-10 起,顶/底档观测不足 20 个;`oi_chg` 的原始分量只有 8 天),报告里是『样本不足』,不是『没信号』。

## 6. 探索性发现(**需另立预注册、在新数据上过零信号对照**)

1. **`mom_60` 的 30 日变化是唯一在三次崩塌前『临门一脚』的分量**:它的不良方向穿越(跌破自己历史 10 分位)在 2021-04 峰前 1 天、2021-11 峰前 21 天(末次)、2025-10 峰前 11 天(末次)——三段里 3/3 落在 −90…0 窗口内;其余分量这一格几乎全是 100 天以上。这与 T-239 的『崩塌是水位塌』结论方向一致(动量先塌),但**幅度**在池化样本上不显著(90 天分位 0.507)。
2. **回撤频率最强的三行都在水平形态上,而且都是日历混淆的行**:`breadth` 的 z 对 `dd90_start` Δ = −47.8pp(分位 0.005)、`mom_60` 的 z −52.6pp(0.002)、`taker_buy` 的 z 对 `dd90_peak` −22.4pp(0.018)。这三行的顶/底档日历差分别是 +365 / +374 / +55 天 —— 『高广度/高动量 ⇒ 之后 90 天不崩』在样本里主要是『2025-2026 那一段没崩』。要真用,必须换成**非趋势**的构造(滚动分位 / 变化量)再预注册。
3. **`taker_buy` 的 Δ30 形态是唯一稳定的『风险确认』量**:顶档(30 日主动买盘份额上升最快)之后 30/60/90 天的收益比底档高 +8.1 / +16.2 / +16.2pp,分位 0.97 / 0.987 / 0.958,日历差只有 −38 天。它可以作为 ⓪ v3 的『加仓确认』候选,但**不是**崩塌预警候选。
4. **三段里没有一段能被 ⓪ 的水平分量解释**:2021-04 与 2021-11 两段发生时,`taker_buy` 的 z 还不存在(2022-01-25 起)、`stable_supply_30d` 的 z 只刚有 3 个月历史、`lend_apy` / `oi_chg` 完全没有 —— 『谁先动』这个问题在早期两段上**大部分分量根本没机会答**。
