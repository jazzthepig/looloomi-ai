## 0. 预注册(S-777 原文,照抄;只算一次)

> **怎么发现的。** T-295(把 detect() 写成 SQL 时逐项对账)查出:238 个参考事件里 **33 个(13.9%)7 日资金费为空**,扩张分位被算成 0.0000 —— 是「缺失」,不是「空头最拥挤」,却按 ≤ 0.10 进了 squeeze;另有 ICP / TLM / FTT 三个零价差零成交合约(ATR = 0、20 日均量 = 0 ⇒ 门槛恒为 0)恒真命中。S-726 / S-768 的 squeeze 读数因此混了一批不是「被挤」的事件。
>
> **写死(只修这两处,别的一字不改):** 事件定义 = S-726;追加两条守卫 —— ① d 日的 f7 为空 ⇒ 不是事件;② ATR14 ≤ 0 或 20 日均 qv ≤ 0 ⇒ 不是事件。重算 S-768 的 ①(原口径 wo = 0 与挪一天 wo = 1 并报):30 天超额中位、随机分位(种子 726,1,000 次)、两半;同时报被剔掉的那批单独的中位。

> **判(与 S-768 ① 相同):** wo = 1 的 30 天中位 < 0、分位 ≤ 0.05、两半都 < 0 ⇒ 「squeeze 反向读数」在干净的事件集上仍成立;否则 S-768 结果段里的「现象站住」作废,T-295 的前向记录按修正后的定义建。**试验计数:纠错复算,不计新试验。**

**执行口径(逐条对齐)**

## 5. 探索性发现(不预注册,只报,任何一条都要另立预注册 + 在新数据上过零信号对照)

1. **伪事件高度集中,不是散布的**:33 条全在 TLM(25)+ ICP(8) 两个合约、2022-06 → 2023-02 一段里。
   换句话说,这不是「13.9% 的事件普遍有噪声」,是**两个空壳合约在一段行情里刷屏**。
   ⇒ 若要继续用 squeeze 这个形态,先按「资金费观测天数 < 9 / ATR=0 / 20 日均量=0」把合约整个剔掉,
   而不是逐事件打补丁 —— 逐事件的守卫在本面板上等价,但按合约剔更省事(需另立预注册)。
2. **被剔掉那批的 30 天中位是正的**(+0.80% wo=0 / +4.20% wo=1),即它们在**稀释**负读数。
   S-726 当年的 −14.3% 其实**低估**了干净读数(−15.4%)。
3. 但被剔掉那批的 H2(2023 年那 6 条 TLM)中位是 **−28.02%**(n=6)—— 这 6 条像真事件。
   探索性:「空壳合约的伪事件」与「空壳合约上的真事件」用这两条守卫分不开,样本也只够提示,不构成结论。
4. **H1 只有 38 条**(2020-2022),H2 有 147 条 —— 两半的证据强度不对称,负号的一致性主要来自 H2。
5. flush 那边两条守卫只剔了 4 条(2022-12 的 FTT/RAY),clean n = 16、两半反号,**仍不登记**。
