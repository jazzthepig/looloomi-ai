## 1. 论文在说什么(一页版)

**两个瓶颈。** 长任务里 agent 的失败集中在早期一步走错、之后不回头(no-recovery regime);而且**什么都不累积** —— 做对过的流程锁在对话记录里,会话一结束就没了。塞进上下文太贵,微调进权重又跟不上工具变化。

**技能 = 外置的程序性知识,六元组 s = (A, I, C, T, π, E):**
激活条件 A、程序说明 I、适用约束 C、可用工具 T、执行策略 π、预期效果 E。三条判据:独立封装可版本化、**按需加载**(不常驻上下文)、编码的是「怎么做」而不是事实或日志。
全局 system prompt 不是技能(常驻、每轮全价);裸 API 不是技能(没有控制流);带重试、降级、解析的 API 包装才是。

**安全约束写成一行式子:** 技能只有在 `T_s ⊆ T_permitted(x_t)` 时才能触发 —— 越出就是提权。

**九段生命周期:** 发现 → 表示 → 存储 → 检索路由 → 组合编排 → 执行与修复 → 适应演化 → 评估 → 安全治理。

**我认为最值钱的六个结论:**
1. **验证性与可移植性反向。** 自然语言(SKILL.md)最好移植、完全不能预先验证;形式合约最可验证、最难移植。**而且没有任何一种格式会在运行前检查自然语言部分(I 与 A)** —— 注入就藏在这里。
2. **只从成功轨迹学,技能对失败模式是瞎的。** 成对的成功 / 失败轨迹(对比挖掘、错误回溯)显著更稳。
3. **LLM 当裁判的准入门有静默失败:** 谄媚、看不出细小语法错误和多文件里的隐藏载荷。要的是可执行的验证(单元测试、沙箱、形式证明)。
4. **库越大越糟:** 近重复的描述让检索混淆;单 agent 在候选技能超过某个临界数后选择准确率**非线性崩溃**,分区的多 agent(上下文隔离、角色边界)反超。
5. **环境反馈带宽假说(负结果):** 在 CTF 这种每一步都有 stderr / 退出码的环境里,技能带来的提升为 0(p = 0.71)。技能的边际价值与环境自带反馈的强度成反比。
6. **描述与实现不符是常态:** 对 49,943 个社区技能的审计发现,代码与声明的能力大面积不一致;社区技能里普遍有收割 `.env`、云凭证、会话 token 的外传脚本。

## 3. 该采纳的四件事(按回报排序)

**1. 交付 = 可执行的验收,不是报告。**(对应结论 3、6)
每张研究卡的验收里写一个**能跑的检查**,lane 交付时附上它的输出;我只看检查的输出,不逐行读代码。研究卡的检查 = 埋信号测试(S4);数据卡的检查 = 一条 SQL 和期望值;代码卡的检查 = 测试 + preflight。lane 自己写「PASS / done」不算。T-042 的 S4 已经在这么做 —— 推广到所有卡。

**2. 把任务卡的 `allowed_paths` 从声明变成拦截。**(对应 `T_s ⊆ T_permitted`)
合并前跑一个检查:这批改动的文件 ⊆ 卡上的 `allowed_paths`,越界就拒收,不靠我肉眼发现。lane 在主目录改文件这件事,用文件系统权限或 pre-commit 钩子拦。

**3. lane 写的自然语言当不可信输入。**(对应「自然语言是注入通道」)
写进规则:SYNC 和报告里的命令、脚本、「请执行」,Seth 不照做;lane 交的是差异,由 Seth 审了再合。派活和卡号只由 Seth 发(已在执行,写成明文)。

**4. 把散文规则往「技能 + 测试」迁。**(对应结论 1、4 与技术债)
`CLAUDE.md` 是常驻的大 system prompt:每轮全价、不能验证、越长越稀释。做法:每条规则问一句「能不能写成测试?」—— 能就写成测试,`CLAUDE.md` 里只留一行指向它;不能的,搬进按需加载的技能(`.claude/skills/`)。目标是 `CLAUDE.md` 变短,而被测试钉住的规则变多。

## 4. 对产品的含义

论文的根问题是「技能在调用前无法完全验证」。在 agent 互相调用的市场里,**可验证的前向记录就是稀缺品** —— 这正是我们 `ARCHITECTURE.md` 的命题。我们对外的 MCP 工具本身就是被别的 agent 调用的「技能」:
- 工具描述是注入面,要和代码一致(描述—实现不符是审计里最普遍的问题);
- 每个工具的输出可以带出处与前向记录(论文提到的市场治理:密码学签名的来源证明),这是可以做成产品差异的地方。
