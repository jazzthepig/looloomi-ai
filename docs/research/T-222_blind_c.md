## 2. 复算口径(逐条写清,与 lane-a 对齐的地方标「对齐」)

- **面板**:`cis_official_daily` 最近一天(2026-11-02)的加密名(`asset_class ∈ {L1,L2,DeFi,RWA,
  Infrastructure}`)= 25 个;`funding_history`(`venue=binance_perp`)有其中 24 个。**对齐**。
- **每日组合资金费** = 当日有数据的那几个名字的日资金费(该日 3 个 8h 结算之和)取均值。
  **对齐** lane-a「24 名日均组合」。
- **年化** = 日均 × 365.25;净值年化 = 净值 ÷ (1400/365.25 = 3.8330 年),非复利。**对齐**。
- **规则 B** = 过去 7 日(只用 t−7..t−1,**不看当天**)资金费均值 > 0;每个 ISO 周第一个有数据日
  重算,两次调仓之间保持上次信号。**对齐** lane-a §4.1 的字面定义。
- **费用** = 每次开关 7.5 bp(现货 taker 4 bp + 永续 taker 3.5 bp)。
- **开关计数**(lane-a 报告没写死,这里是复算出来的约定):**内部切换次数 + 起手那一次开仓
  (路径以持仓开头才计)+ 末尾那一次平仓(路径以持仓结尾才计)**。规则 B 周换仓的路径
  「以空仓开头、以持仓结尾」⇒ 39 次内部切换 + 0 + 1 = **40**,与 lane-a 的 40 一致;规则 A 常开
  路径全程持仓 ⇒ 0 + 1 + 1 = **2**,与 lane-a §4.1 表里 A 的「2 次开关」也一致。
  两种约定在规则 B 上差一次开关(净 18.274 % vs 18.199 %)。
- **随机门控对照构造**:把开仓天数随机切成与原路径**同样多**的正长段(20 段)、闭仓天数同样
  切成 20 段,交替排布 ⇒ 起始状态、开关次数(40)、开仓天数(972)与原路径完全一致 ⇒ 费用完全
  一致,只有「哪些天开仓」随机。零分布走 `apparatus.null_distribution`(n=1000,种子 222),
  分位走 `apparatus.percentile_of`。
- **月度资金费** = 该月 24 名日均组合资金费的**求和**(单位 %/月)。月度对照(③')另算:
  「BTC 当月回报」= 本月末收盘 / **上月末**收盘 − 1(上月末取该月最后一个有收盘的日历日)。
- **BTC 收盘源** = `ohlcv_daily.source = 'binance_hist'`,1492 个日历日(2022-10-01→2026-10-31),
  **无缺日**。
- **未来 30 日** = 月末收盘 → 该日 + 30 个日历日后的第一个有效收盘(窗口 7 天)。入口 / 出口下标
  与 `apparatus.price_on_or_after` 逐月对账:**0 处不一致**。

## 3. 复算中撞到的三处坑(Seth 主持对账时可直接看这三条)

1. **`funding_history` 里 `venue=binance_perp` 的符号有 111 个**,不是 24 个(还含 ALGO / ALICE /
   1000SHIB 这类)。面板必须由 `cis_official_daily` 的加密名圈出来,否则「24 名等权」根本不是
   同一个东西(第一次跑我按全表算,得到 111 名的组合)。
2. **BTC 收盘在 `ohlcv_daily` 里有四个源**,只有 `binance_hist` 是完整日频:
   `binance_hist` 1492 天无缺日;`coingecko` 1318 天且缺 2025-01…05、止于 2026-09-16;
   `coingecko_pro_ohlc` 只有 432 天(自 2025-08-26);`hyperliquid` 只有 15 天。**换源会换数**:
   用 `coingecko` 算未来 30 日口径只剩 n=38,ρ = +0.094(p = 0.574);`coingecko_pro_ohlc` n=14,
   ρ = −0.046(p = 0.876)。报告里必须钉住源,否则「月度 Spearman」没有可比性。
3. **「BTC 月回报」有三种读法**,我一开始把「上月末」写成了「月末前一天」(等于取月内最后一天
   的收益),同期 ρ 变成 +0.139、p = 0.357,与 lane-a 的 +0.368 对不上 —— 定位后才发现是**我的
   bug**,不是口径分歧。修正后三种读法都在 +0.34…+0.37 之间(见下表)。

## 4. 探索性发现(**需另立预注册、在新数据上过零信号对照**)

> 下列三条是为对账而顺手算的,不是预注册的检验,**不要**当成 T-222 的结论用。

- **同期口径对「月度资金费」和「BTC 月回报」的读法不敏感**:月度资金费用月内求和还是月均日值,
  ρ 分别是 +0.3681 / +0.3687;BTC 月回报用「上月末→本月末」「本月首日→本月末」「月内日收益算术均值」,
  ρ 分别是 +0.3681 / +0.3449 / +0.3525。也就是说 lane-a 的 +0.368 不是某个脆弱读法的产物,
  这条「费率高的月份 = BTC 当月涨过的月份」在四种读法下都成立。
- **随机门控对照的净值不是 0**(均值 10.864 %):随机挑日子持仓也吃到了样本期资金费的整体正漂移。
  所以判据 (d) 必须比**分位**(1.000),不能比绝对值;若拿 B 的净值去减对照均值,会得出
  「门控只多赚 7.4 %」这种错觉。
- **规则 B 周换仓的开仓天数 972 / 1400(69.4 %)**:门控只关掉约三成日子,毛收益只比常开高
  1.55 pp(21.274 % vs 19.726 %),而费用吃掉 3.0 %(40 × 7.5 bp)—— 净收益比常开低 1.30 pp。
  **门控相对随机门控有效(分位 1.000),但相对常开不值**,这两件事不矛盾,是两个不同的对照。
