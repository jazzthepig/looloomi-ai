## 8. 结果里还看到了什么(探索性 —— 需另立预注册、在新数据上过零信号对照)

1. **幽灵仓把一张赢家变成 4 年的浮盈**:第 2 张票是同日止盈 +1.65R,旧实现让它永不平仓,
   于是旧袖套净值 = 「1 张已平的票 + 1 张不掉的浮动仓」,18 张票的袖套被报成 2 张票的袖套。
   ⇒ 任何「多票并发 + 组合 NAV」的旧数都该先数「进场票数 / 末日持仓数」再信回撤。
2. **预注册口径的可执行性本身要先验**:③ 池 69 天抽 18 张不重叠票**不可行**(实测 1000/1000 次凑不满)。
   预注册若写死一个不可行的对照,执行者一定会偷偷换一个池 —— 而换池会改百分位(36.4 → 85.7)。
   ⇒ 预注册该写「对照池 + 每次抽样允许的票数 + 票数不足时怎么办」。
3. **资金费口径(盯市 vs 出场兑现)对结论的影响 = 0** ⇒ 「盯市与出场各算一次」这条 bug 在四个数上是**无害**的;
   报它是为了让账本干净,不是为了改结论。真正的杀伤在仓位生命周期。
4. **旧口径的「削 0.5pp」符号读法**:`dd_reduction_pp` 为负 = 削回撤(combined 比 core 浅)。
   旧 −0.5170 = 削 0.52pp;新 −0.2490 = 削 0.25pp。**两版都是「削」,没有变号** —— 但旧文「削 0.5pp」是幽灵仓的结果,
   真实袖套几乎削不动回撤(0.25pp)却仍要付 0.4 个 NAV 单位的收益 —— 性价比更差,不是更好。
5. **坏 NAV 会把「显著为负」洗成「分不开」**:袖套 NAV 路径的 `ab_test` p(b≤a) 从 **0.7725(分不开)**
   变成 **0.9525(B < A)**。原因是幽灵仓把袖套做成「1 张已平的票 + 1 张不掉的浮盈」——
   一条**近乎单调、不回撤**的路径,块自助抽出来的分布挤在一起 ⇒ p 值虚高、看不出显著。
   ⇒ **NAV 路径上的统计量(p 值、最大回撤、Sharpe)比 NAV 终点值更脆**:终点对得上不代表路径对得上。
