## 5. 11-05 修正:成熟期过滤(去前视)—— 修复前后对照

**问题**:v1 走步取历史截面时只比月份(`r["month"] < m`),但历史截面的 30 天前瞻收益要到 `d' + 30d` 才成熟。
月末 m 的决策日 D 落在本月内时,上一个月末(及更近)的截面常常**还没到期**就被算进 IC̄ ⇒ 前视。
S-734 原文写的是「m 之前**已到期**的最近 24 个月末截面」—— 是实现没照字面做,不是判据被改。

**改法**(`t249_ic.py` 走步段):历史截面 d' 只有在 `d' + 30d ≤ D`(D = 该组该月的 as-of 截面日)时才算已到期;
本月无合格截面时取该组 ≤ 本月末的最近截面日。旧口径(只比月份)保留在 `legacy_month_filter` 字段里逐格对照,
汇总在 `t249_results.json` 的 `maturity_filter` 段(`cells_n_changed` / `cells_mult_changed` / `cells_t_changed` /
`max_abs_delta_mean` / `max_abs_delta_t` / 逐格 `rows`)。

**修复前后(同一协议、同一份缓存,只差这一个过滤)**:

| (a) crypto | +0.005800(t 1.3259) | +0.005800(t 1.3259) | 0(该组乘数与成熟度无关) |

**结论:判据结论不变**。(a) t = 0.1047 < 2.0、(c) 分位 0.463 < 0.95 ⇒ 两条仍不满足 ⇒ 乘数保持 1.0,只记录。
量级上,前视让 (a) 的均值虚高约 3 倍(0.002276 vs 0.000672),但**从不影响判据的通过 / 不通过**。
v1 提交信息写的「判据 (a)(c) 不满足,乘数保持 1」在新口径下依然成立。
