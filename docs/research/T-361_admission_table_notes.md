## 3. 三处必须由 Seth 拍板的口径(其余数都在 `t361_results.json`,换判据不用重跑)

**(a) 尺寸规则把账户交给了家族。** S-835 写的是「调到它自己占账户风险 10%」。我按 S-834 自己的口径实现:
边际方差贡献 `cov(族贡献, 账户) / var(账户) = 0.10`,二分。这些坟场袖套自身年化波动只有 **1%–17%**
(账户 36.7%),于是「占 10% 的风险」要给它 **33%–98% 的资金**;叠加后账户年化被家族主导
(H4:35.75%→16.99%),(iii) 的「最差 20 日变好」有一半是**低波稀释**的记账效应,不是风险被修好了。
若改成「波动份额 10%」(w = 0.10 × 36.7% ÷ σ族):H4 0.22、S-681 H2 0.37、S-642 0.61、S-808 0.61、
S-736 两版 0.46/3.7、S-810 3.7(不可能)。**这两条口径给出的答案不同,请指定用哪条。**

**(b) (ii) 的零分布统计量是我定的。** 用 `apparatus.circular_shift`(族的日收益序列,block 1,500 次,种子 361),
统计量取「叠加后账户年化 − 原账户年化」,`p_upper < 0.10` = 实际对齐在 500 次错位里排进前 10%。
注意:错位不改变族自身的均值,所以这条实际量的是**对齐**(族与账户的同涨同跌)是否显著地好于随机,
不是「族自己赚不赚」。若你要的统计量是别的(例如协方差、或族自身收益),原始数都在 json 里。

**(c) (iv) 对四个族是空的**(见上)。要真正分开,H2/H4/S-808/World50 需要一条更早的账户口径。

## 5. 探索性发现(假设之外;每条都要另立预注册、在新数据上过零信号对照)

1. **坟场袖套的波动只有账户的 3%–45%** —— 任何「占账户风险 X%」的尺寸规则都会把它们放大成账户主体。
   对这一族,「它值不值得给这么多资金」比「相关够不够低」更前置。
2. **压力月里,加密反向族与账户同涨同跌**:S-681 H2 ρ=+0.63、S-642 +0.75、S-736 +0.87。它们是账户
   crypto 腿 + R-v2 同一个 β 的反号,**不是独立引擎** —— 「多空互补」在这些族身上不成立。
3. **World50 的 p_upper=1.000**:股权腿与账户的股权腿同涨同跌,把它当第二个引擎是加重集中度而不是分散。
4. **所有族都让最差 20 日变浅(−19.4% → −0.6%…−13.5%)**,但几乎全部来自低波稀释,不是修补了 R-v2 的
   假突破成串;因此 (iii) 这一条在本轮基本不携带信息。
