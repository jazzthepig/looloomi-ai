**双侧读法(口径说明,不是新规则)。** 预注册的「分位 ≥ 0.95」是单侧口径,而同一条规则又允许「两半同号」的全负 ΔR —— 单侧口径会把每一个负向效应机械地判成不显著(分位 ≈ 0)。所以这里另记一个双侧标记:实际值落在零分布的两端(双侧分位 ≤ 0.05)。**预注册的 candidate 判定不改**,双侧只作参考:

## 4. 诚实段

**① 多重比较。** 8 个量 × 2 半 = 16 次检验。卡上的门槛(分位 ≥ 0.95)没有做多重校正;Bonferroni 对应 0.05/16 = **0.003**。所有量都用同一个种子 235 ⇒ 零分布跨量相关,不能当独立检验处理。另外所有分位都用 iid 置换,R 在时间上成簇 ⇒ 零分布偏窄,真实显著性大概率比报出来的弱。

**② 本地 bars 与 DB 的 `ohlcv_daily`(source=binance_hist)对不上 —— 量纲变了。** 重叠 298295 行里收盘价不一致 187857 行(比值中位 1.000564,即价格本身几乎没动),但 **volume 不一致 208810 行**,比值中位 0.226014,且 **163/183 个符号**受影响(其余符号逐字节相同)。结论:`ohlcv_daily.binance_hist` 的 volume 在 10-21 快照与 11-05 之间被换过定义/来源,本卡只用本地快照这一套 vintage(不混用)。**这是给 Seth 的工程问题:任何依赖 `ohlcv_daily.volume` 的结论都要先确认量纲。**

**②′ 更正:上一版把「①量能比那张表」标成作废是过度谨慎。** 去掉 DB 混用重跑后,①量能比(以及其余全部本地量:⑤⑥⑦ 与 ②③④ 的档位)在 d 与 d−1 两个口径下 **767 张票的档位逐位相同**,ΔR 也逐位相同 ⇒ 上一版的 DB 混用实际上没有落到任何一张票的可观测量上,那张表**不作废**。只有 ⑧⓪ 变了(见 ④)。

**③ 票集本身的缺口。** ①`r_tickets_paper` 读到 0 行 ⇒ 前向纸面票 0 张:纸面书的 `r_tickets_state.last_d` 已经走到 2026-11-03,但 `r_money_daily` 的 16 天 nav 恒为 1、ret 恒为 0⇒ 前向从未开出过一张票,所以卡上说的「2026-06-21 起的票」实际不存在;②长票 **2022 年整年 0 张**(2020/2021/2023/2024/2025/2026 才有),所以卡上规定的第一半(2020-03→2022-12)只剩 2020+2021 两年的票,H1 与 H2 的样本量严重不等;③3 张 2024-11 的票在快照时仍未出场(r 为 null),已剔除;④文件里另有 241 张空头票(带 exit_reason:sma20/stop),属另一套策略,未混入。

**④ ⓪ 相位用的是 v1.1。** `cycle_vector_daily` 现在只有 `['cycle_vector v1.1 (11-04: funding ← binance 2020 起; 不写 d 之后的行; code_ref 变了整条重算)']`,deterioration 非空 2105 行,区间 2021-01-29 → 2026-11-03;脚本按行取(库里只有一个 code_ref,不过滤也只有一个版本),所以本轮 ⑧ 用的就是 **v1.1**(上一轮用的是 v1,起点 2022-01-25)。v1.1 把起点前推到 2021-01-29 ⇒ ⑧ 的缺失率从 10.4% 降到 3.8%,767 张票里 218 张重新定档,H2 的 ΔR 从 0.5317 变成 0.4592。库里不再有 `cycle_vector v1` 的行 ⇒ 想要 v1 口径得另跑重建。

**⑧ 零分布的接线曾经是坏的(本次修正,重要)。** 第一次跑出来的每一个格子的 `null_pct` 都是 `None`,`null_note` 写着 `NoOpNull: 零分布没有方差` —— 原因不是数据,是代码:旧的打乱函数只打乱了下标顺序,而过滤条件仍然按**原档位**取子集 ⇒ 每次抽样的顶档/底档集合完全相同 ⇒ ΔR 每次都等于实际值 ⇒ 零分布零方差。后果:预注册里的「随机分位 ≥ 0.95」这一条**从来没有被真正检验过**,「无候选」有相当一部分是这道坏门造成的,不是统计结论。修正 = 按预注册原文「随机打乱标签」把档位重新分配给票再算 ΔR,零分布仍只用 `src/data/evaluation/apparatus.py`。**本次的 % 是第一次有效读数。**为免混淆,预注册的 candidate 判定一字未改,双侧读法单独出列(见 §3)。

**⑤ 主动买盘的两处口径偏离。** ①卡上写「d 日 taker 买量占比」,s695 用的是 d−7..d−1 的均值;本卡按卡上写的取 d 日单日值(买量占比 = ratio/(1+ratio),是 s695 的 ratio 的单调变换 ⇒ 分档完全相同);②`deriv_metrics_daily` 的 taker_ratio_mean 是 Binance metrics 的日均,入库有滞后,所以 d 口径有可能用到当天收盘后才落库的数据 —— 这就是为什么 d−1 口径必须一起跑。

**⑥ 缺失率。** 每个量的缺失率见各节;缺失一律 NA 不补 0。早期票(2020 年)缺日线是因为本地 `_bars_early.jsonl` 只覆盖 74 个符号。
