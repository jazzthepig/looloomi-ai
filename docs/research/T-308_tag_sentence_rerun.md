## 一、错在哪(一句话)

`events` 一行 = 一个 `kind` + 一坨 `symbols`。标题
**『Extend the Monitoring Tag to Include A … and Remove the Seed Tag for B』**
被整行判成 `monitoring_tag_removed`,种子标签那一支被错当成「监控标签被移除」。
按标题分句后:监控标签**新增** 43 次曾被记成「移除」,涉及 **54 个代号**
(行级口径只有 80 个代号有「打上」记录,分句口径是 134 个 —— 差 54,与卡上数字逐位吻合)。

## 三、分句规则(分析脚本内,不改入库)

三类语义分开:`Extend the Monitoring Tag …` ⇒ **监控标签新增**;`Remove the Monitoring Tag …` ⇒ **监控标签移除**;
`Remove the Seed Tag …` ⇒ **种子标签移除,与监控标签状态无关**(不进状态机)。
动词承前(`… Remove the Monitoring Tag for ZEC and the Seed Tag for ENA` ⇒ ENA 走种子标签分支);
`Change the Monitoring Tag Inclusion Frequency` 只改制度参数,不产生代号。

被修正的 8 行(全部是 db `kind=monitoring_tag_removed` 但实际含「新增」的行):

| 公告日 | 行级判 | 分句判(新增 / 监控移除 / 种子移除) |
|---|---|---|
| 2024-01-04 | 12 个全判移除 | 10 / 0 / 2(GMX, SUSHI) |
| 2024-07-01 | 13 个全判移除 | 11 / 2(MLN, ZEN) / 0 |
| 2024-10-03 | 7 个全判移除 | 5 / 0 / 2(PENDLE, SEI) |
| 2025-01-02 | 8 个全判移除 | 2 / 2(CVX, SUN) / 4 |
| 2025-04-03 | 13 个全判移除 | 10 / 0 / 3 |
| 2025-07-09 | 4 个全判移除 | 0 / 1(ZEC) / 3 |
| 2025-10-09 | 7 个全判移除 | 1(WAN) / 2(GPS, MBL) / 4 |
| 2026-03-06 | 12 个全判移除 | 9 / 1(FLOW) / 2 |
| 2026-04-14 | 8 个全判移除 | 6 / 0 / 1(XAUT) |

副作用(口径变化):`MLN` 2024-07-01 被移除监控标签、2026-04-14 又被**加回**;行级口径因末次事件是 removed 而一直判它「不在标签上」。
另有标题噪声词被生产解析器当成代号:`FOR`(2024-04-03)、`HIGH`(2026-04-14)、`D`(2026-01-02,单字母)—— 分句口径按公告套话表挡掉。

## 四、tag_d 改存实际打标签日(卡第 2 项)

T-303 的 `tag_d` 存的是**计划日(信号日)**,字段名与内容不符。修订版:tag_d = 状态机里该代号 **off→on 的那一天**
(= 实际打标签日);class-2 已是该日,不变。改后 `class1_rows` 同时给 `plan_d`(信号日)与 `tag_d`(实际打标签日)两列,
可直接核对两者差值(候选里多为几个月)。

## 五、口径映射表 T-303 ↔ T-278(卡第 4 项)

同一生成器(T251)、同一 40% 档、同一 R-v2 规则;差异只在**账本起点**与**窗口**:

| 账本 | 起点 / 窗口 | 有 R 的成交票 | 总 R |
|---|---|---|---|
| **T-278(S-757 下架)整本** | scan 2020-07-01 → today−1,整本不过滤 | **145** | **54.3331** |
| T-278 台账窗口子账本 | 进场日 2022-02-17 → 2026-10-14 | 106 | 18.4736 |
| T-303 口径 B 窗口子账本 | 进场日 2023-07-26 → 2026-10-14 | 67 | 19.4042 |
| T-303 口径 A 窗口独立起账 | 2023-07-26 起独立起账 | 155 | 110.0372 |

- **对齐验证**:本卡用 T-278 自己的 scan 区间跑整本账本,得 **145 张 / 54.3331**,与 T-278 报告**逐位相同**;
  同一口径下「只下架」规则 = 145 张 / 54.3331 / **ΔR = 0**(交叉验证通过)。
- **155 vs 145 vs 67 的来源**:155 是「窗口内独立起账」(起点净值与占用不同,票最多);
  145 是「全书整本」;67 是「全书整本 + 窗口过滤」。**三个数不是同一口径,不能并排比。**
- 同口径并排(整本 145 张 / 54.3331):只标签(行级或分句)= 144 张 / 55.3489 / ΔR +1.0158;只下架 = ΔR 0。

## 七、结果里还看到了什么(探索性 —— 需另立预注册、在新数据上过零信号对照)

1. **§七.2 重写(T-303 报告)**:T-303 原文写「4 个候选全是 XEM(3)+ STX(1) …… 候选池和监控标签池几乎不相交」。
   修正后 class-1 候选是 **12 张、涉及 9 个代号**(9 个代号这个数来自卡上 lane-c 的复核数字,
   **本轮未独立复核逐张代号清单**,下一轮补),覆盖面比原文宽,但**「几乎零交集」的形状不变**:
   候选池仍然是极少数几个代号,不是全池。
2. **被错判的方向是单边的**:错判把「新增」写成「移除」,于是行级口径**低估**监控标签覆盖面
   (80 个代号有打上事件 vs 分句 134 个)。这类错误对「剔除型」规则是**保守方向**(少剔除 ⇒ 少副作用),
   对「在标签上 ⇒ 不开票」这类规则是**乐观方向** —— 结论方向敏感,不要默认它无害。
3. **「持有期间被打上标签」两口径都是 0 张**:这条规则真正会发生的场景在历史上一次都没出现过。
4. 两条规则(下架 + 标签)在 R-v2 账本上**仍不重叠**:下架 ΔR = 0,标签 ΔR = +1.0158,合起来 = 只标签。

## 八、诚实与限制

- **只算不判**:本卡不给「该不该上这条规则」的结论。
- 分句只解决**同一标题内多语义**的问题;标题本身写错、代号漏写仍需解析层修(本卡不动 `src/`)。
- 白名单 = 27 行公告里出现过的代号形态全集(生产解析器抓到的);**标题里若有生产解析器漏掉的代号,本卡也抓不到**
  —— 解析层的漏与本卡的漏是同一个洞,不是两个独立证据。
- 口径 A(独立起账)与口径 B(全书轨迹)数字不同是正常的;**规则效应在两口径同号**(行级 +1.0158 / 分句 +2.904)。
- 零信号基线未跑(第六节),本报告不引用任何零分布数字。
