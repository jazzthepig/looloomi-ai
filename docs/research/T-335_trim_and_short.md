# T-335(S-811)—— Jazz 的做空写法:过热区卖 50% 多头、用利润分批加空、扛单无价格止损、预算 = 落袋利润

> 只读研究:数据 = Supabase `perp_bv_daily` / `v_funding_daily`(不写库);零分布与盈亏只走 `src/data/evaluation/apparatus.py`。**试验计数:做空族 +1。**

## 0. 预注册原文(S-811,照抄)

```text
## S-811 — Jazz 的做空写法:**高位卖掉多头的利润、用利润分批加空、扛单不设价格止损**,风险上限 = 刚落袋的利润 —— 对「一直拿着」与「只减仓不做空」—— 预注册(Seth,2026-11-11 03:18 UTC;Jazz 11-11「很多时候空头需要扛单,高位卖了多头的利润加仓空头,而不是裸空到止损线就止损」;这种「减多 → 用利润加空 → 回落后买回」的组合动作从没算过;交 B 道 T-335)
**为什么。** S-736 / S-808 / S-809 都是**裸空 + 紧止损**:217 / 350 张在 2 天内被打掉。Jazz 的写法把空头放在组合里:空单的本钱是刚从多头上落袋的利润,所以可以扛;越涨越加(均价抬高),回落时一起兑现,再把多头买回来。它问的不是「能不能猜对顶」,而是「在过热区把一部分多头换成空头,整个账户是不是更好」。
**写死(BTC 为主,ETH 同口径只报):** 价格 = Binance BTCUSDT 永续日线(`perp_bv_daily`),2019-12 起;基础持仓 = 1.0 倍 BTC。
- **过热区(只用 ≤ d 的数据):** 收盘 / 200 日均线 − 1 ≥ 其扩张 90 分位(崩盘图谱 P2)**且** BTC 资金费年化 7 日均 ≥ 其扩张 85 分位(拥挤多头,`v_funding_daily`);各 ≥ 250 个观测。
- **进(过热区第一天收盘):** 卖掉 50% 多头;利润预算 B = 0.5 × 账户 × max(0, 收盘 / 90 天前收盘 − 1)(卖掉那一半近 90 天的涨幅)。第 1 笔空 = 0.25 倍名义;此后价格较第 1 笔再涨 +10%、+20% 各加 0.25 倍(最多 0.75 倍,净头寸最低 −0.25 倍)。**不设价格止损**;唯一的风控:空头累计浮亏 ≥ B ⇒ 全部平空、多头回到 1.0。
- **出:** 收盘第一次低于 50 日均线 ⇒ 全部平空、多头买回到 1.0;或首笔空起 90 天到期同样处理。期间过热区再触发不叠加新的一轮。
- 成本 7.5bp × 换手,资金费按持有期实计(空方收正费率)。
**三臂:** HOLD(1.0 倍一直拿着)· TRIM(同样的进出时点,只减 50% 再买回,不做空)· **TRIM+SHORT(Jazz 的写法)**。
**判(全过才 ✅):** (i) TRIM+SHORT 总收益 > HOLD **且** > TRIM(空头那部分本身要加分);(ii) 最大回撤不比 HOLD 深;(iii) 随机对照:把「过热区」日程整体平移(`apparatus.circular_shift`,1,000 次,种子 811),TRIM+SHORT − HOLD 的实际值 ≥ 零分布 90 分位;(iv) 逐轮列出(每一轮的进出日、加了几笔空、空头盈亏、是否触发预算平仓),**多数轮次空头盈亏为正**。
**诚实:** 2019–2026 的过热轮次大概只有 5–8 轮,检出力很弱 —— 逐轮表比汇总数更重要。DECISIONS 10-21 定过「降敞口 = 卖现货 + 放贷,不开对冲空单」、③ 只在 0–1 倍;这条若过,要 Jazz 改那条规则才能动钱。**试验计数:做空族 +1。**
```

## 1. 口径与本卡读法(有歧义处写死)

| 项 | 本卡取法 |
|---|---|
| 基础持仓 | A0 = 1.0(归一),全仓 BTC(现货腿,不吃资金费);`perp_bv_daily` 收盘成交 |
| 过热区 | 收盘/MA200 − 1 ≥ 自身扩张 90 分位 **且** 资金费年化 7 日均 ≥ 自身扩张 85 分位;两个分位都只用 ≤ d 的数据、各 ≥ 250 个观测 |
| 资金费口径 | `v_funding_daily.funding_rate` = 每个 8h 间隔的均值,`n` = 当日间隔数;日内合计 = rate × n,年化 = 日内合计 × 365 |
| 一轮 | 过热区的**第一段连续区间的第一天收盘**进场;该段被这一轮占用后不叠加新轮;下一段过热(且上一轮已平)才开新一轮 |
| 空头名义基准 | 进场时账户值 a_after(卖 50% 多头、已扣成本);三笔 = 0.25 / 0.50 / 0.75 × a_after |
| 预算 B | 0.5 × a_after × max(0, 进场收盘 / 90 天前收盘 − 1);**空头累计浮亏 ≥ B ⇒ 当日收盘全部平空 + 多头买回 1.0**;从进场的次日起判 |
| 出场 | 收盘第一次低于 MA50,或首笔空起 90 个日历日到期;两者动作相同 |
| 「多头买回到 1.0」 | 多头买回**进场前的数量**(1.0 倍 BTC);轮后剩下的现金留在账户里—— 那正是「刚落袋的利润」,也是下一次做空的本钱;TRIM 臂同口径 |
| 成本 | 7.5bp × 每次成交名义(买 + 卖各算一次) |
| 资金费 | 持有日 (进场日, 平仓日] 实计;空方收正费率(按当日名义 × 当日资金费率) |
| 轮内检查顺序 | 资金费 → 预算风控 → 出场 → 加空(+10% / +20% 较第 1 笔) |

## 3. 诚实与边界

- 轮次极少(见上表),汇总数的检出力很弱 —— **逐轮表比汇总数重要**;任何一条判定都只是「在这一小段样本上没有反例」,不是「有效」。
- 「多头买回到 1.0」= 买回进场前的数量、利润留现金(本卡读法)。另一读法(全额换回 BTC)会让轮后仓位略大于 1.0 倍,结论方向不变、幅度略大。
- 永续空单开仓没有现金流入、平仓也没有名义本金流进流出,账户只拿到**已实现盈亏**;第一版脚本把平仓名义当成流入(账户凭空多出约 2 倍名义)时,BTC 的 Δ 被虚报成 +5.0,已修正为 +0.12 量级 —— **修的是记账,不是结论方向**。
- 随机对照把**整条过热区日程**循环平移;平移后 MA50 / 资金费 / MA200 的可用性仍按原日期取(指标本身不重算),这是 S-811 写死的做法。
- ETH 只报,不判定。
