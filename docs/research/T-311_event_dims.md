## 0. S-790 原文(照抄,只算一次)

**为什么(本体论):** HIGH_DIM_ONTOLOGY 说最深的对象是 Entity / Decision,β+ 来自「离因更近」。S-776 / S-778 把按币的资金面(散户多空、资金费、杠杆)这条「因」收了卷 —— 但那些是**人群**的量。交易所的上币 / 打标签 / 下架是**一个实体的决定**,对手盘族已经量出它们单独之后 30 天跑输 16–38%(S-751 / S-753 / S-763 / S-770 / S-781)。问题是:把这些决定当成 Asset 空间的维,在 S-776 最强的价格相位模型之上,还多不多给信息 —— 尤其在「最低五分位」(② 的排除用法)。

**写死:** 框架逐字照 S-774 / S-776(`docs/research/t293_asset_flow.py`、`t296_ablation.py`:每周一 t,2023 年第一个周一 → 最后一个 x30 已到期的周一;宇宙 = `asset_flow_daily` 有 vec 的币;目标 x30;走步 Ridge alpha 10,只用 d' < t − 30 的行训练)。

- **P(基线)** = S-776 的 P 臂:mom7 / mom30 / vol30 / vratio / dd90 五维。
- **E** = P + 6 个事件维(全部按 t 当天收盘已知):① Binance 现货上币公告距 t ≤ 90 天 ② Binance USDT 永续上线公告 ≤ 90 天 ③ Upbit 韩元首次上币 ≤ 90 天(`binance_event_watch` 三类的 announced_at)④ t 当天挂着 Binance 监控标签(`events.monitoring_tag_changes` 逐句状态机,与硬规则同一个)⑤ 过去 30 天内有 squeeze 事件(`crowding_watch` kind = squeeze,d ≤ t)⑥ 过去 365 天内被宣布整币下架。全部 0 / 1,居中到 ±1 与价格维同尺度。
- **主判(排除的用法):** 每周 E 的最低五分位 x30 均值 − P 的最低五分位 x30 均值:全样本均值 < 0、NW t(滞后 5)≤ −2、两半(2023-01 → 2024-12 / 2025-01 →)都 < 0 ⇒ ✅。**金额判据(S-779 附注):** E 的 Q5 − Q1(扣 20 bps)≥ P 的,且最低五分位的**均值**(不只中位)更低。**副判:** IC(E) − IC(P) 均值与配对 NW t。报每一维单独加进 P 的边际(只报,不判),每周被事件维标记的币数(稀疏度)。
- **后果:** ✅ ⇒ 前向记录(在 `asset_flow_forecast_daily` 旁加 E 臂,周一预测、到期结算)+ 事件维进 Asset 空间的向量(另立实现);❌ ⇒ 事件只作硬规则与描述(现在的用法),不进模型。**试验计数:高维族 +1。**

## 1. 口径与两处披露(偏离 S-790 的地方)

1. **事件维在每个交易日都算,不是只有周一。** 走步的训练集是**全部日频行**(S-774 / S-776 同口径),只有评估是周频;若事件维只在周一刻意,训练集就得换口径(与基线不可比)。CSV 交付物仍按验收要求落「每周一 × 每币」。
2. **① ② ③ 用 `binance_event_watch.d0`(公告日)**,不是上市日:`listing` 行的 d0 = 公告日(2018-05-16 公告、05-18 上市),`perp_listing` / `upbit_krw_listing` 的 announced_at 与 d0 同日。三类的 announced_at 日期与 d0 一致,所以「按 t 当天收盘已知」成立。
3. **④ 监控标签用的是本地副本**:生产的 `src/data/market/events.py::monitoring_tag_changes`(Seth 2026-11-08 未提交的 `20261108-1500b`)在本轮跑的时候还没合进 main。脚本**先尝试 import 生产函数,失败才用本地副本**(与待合并版本逐字一致:_TAG_REF / _TAG_VERB / _TAG_STOP + 同一函数体)。生产合进后重跑会自动走生产版;**若生产版在合并前再改,本地副本必须删掉重跑**。

## 3. 主判与金额判据(结果)

| 判据 | 结果 |

两个判据都是**否**,方向与 S-776 的「因」维族一致:在价格相位(P)之上,再叠一层横截面维,主判的「排除用法」没有站住。

**判据是同快照内比较**:E 与 P 用**同一份数据、同一套走步、同一批周**,所以「E 相对 P 没有增量」这个相对结论是内部一致的;但它**不能**被读成「与 S-776 已发表的数字对比」—— 那一侧的基线已经漂了。

## 4. 结论(按 S-790 写死的后果分支)

**❌ 事件维不进模型。** 事件继续只作**硬规则与描述**(现在的用法:上币 / 监控标签 / 下架 / squeeze 各自触发排除或警示),不进 Asset 空间的向量,不进截面模型。**试验计数:高维族 +1(本卡 = 第 1 个「实体的决定」族)。**

配套:事件维是否进 Asset 空间的向量这条另立实现的路,**现在不开了**。

## 5. 探索性发现(假设之外;每条都需另立预注册 + 新数据上的零信号对照)

2. **P 的尾部水平没随 IC 漂。** IC 掉 14%(相对),最低五分位只动 0.00017。⇒ 「排序力」和「尾部幅度」在这次刷新里是两条独立的东西;若以后要用 P 做排除,盯尾部而不是盯 IC。*(探索性 —— 需另立预注册、在新数据上过零信号对照。)*
3. **事件维的输入天然稀疏且高度重叠。** ①②③ 都是「交易所的决定」,时间上高度共线(同一个币常常在同一周既上现货又上永续),④⑥ 也是公告族。⇒ 即便某一维单独有边际,6 维一起进 Ridge 也未必能分开;每维边际只报不判是对的。*(探索性 —— 需另立预注册、在新数据上过零信号对照。)*
4. **监控标签的状态机比「第一次打标签」是更长的对象。** 27 条公告里只有 9 条带移除(其中多数是「Remove the Seed Tag」,与监控状态无关),所以「当前挂着标签」的币数会随时间只增不减地漂。⇒ 若将来把标签维当横截面维用,必须按状态(挂/摘)算而不是按首次事件算 —— 这正是 T-303 / T-308 分句的价值所在。*(探索性 —— 需另立预注册、在新数据上过零信号对照。)*
