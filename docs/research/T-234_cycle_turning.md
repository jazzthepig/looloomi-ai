## 6 · 为什么亮不出来(机制,读结果必看)

1. **分量不够 ⇒ 根本没有相位**。`state_daily(entity=panel)` 的 8 个分量覆盖:

   | 分量(feature) | 非空天数 / 2,864 | 最早非空 |
   |---|---|---|
   | `breadth_above_ma50` | 2,864 | 2019-01-01 |
   | `vratio_30_180` | 2,864 | 2019-01-01 |
   | `mom_60` | 2,804 | 2019-03-02 |
   | `stable_supply_30d` | 2,470 | 2020-01-30 |
   | `taker_buy_share_30d` | 2,109 | 2021-01-25 |
   | `stable_lend_apy_7d` | 1,363 | 2023-02-10 |
   | **`funding_7d_ann`** | **56** | **2026-09-09** |
   | **`oi_chg_30d`** | **8** | **2026-10-27** |

   ⇒ 窗口内 `n_components` 只有 **3–7**(从未 8/9);`MIN_COMPONENTS=6` 之下 `det=None`、`phase=None`
   (2020 全年只有 3–4 个分量)。**2020 年的段在当前口径下不可能有 turning**。
2. **扩张窗口 + `MIN_HISTORY=365` 是结构约束**:任何分量都要 365 天历史才有 z ⇒ 2020 年(数据从 2019-01-01 起)
   整年没有 z,与数据质量无关。
3. **`shift_pct ≥ 0.75` 这道门槛在真正的暴跌里经常不成立**:2022-06-18(唯一有信号的大跌中段)`det = −1.187` 但 `shift_pct = 0.717`;
   2022-11-21(FTX 谷)`det = −0.445`、`shift_pct = 0.108`。规则要的是「搬家距离在自身扩张历史的高分位」,
   暴跌里的状态**位移**未必比之前的震荡大。
4. **亮灯滞后**:4 段 turning 区间 = `2022-05-12→07-18`(68 天)、`2023-06-11→10-22`(134 天)、
   `2024-05-03→05-20`(18 天)、`2025-01-12→04-21`(100 天)。只有第一段落在 ≥30% 回撤段内,而且是**跌到中段才亮**;
   其余三段落在没有 ≥30% 回撤的时段(2023 年 BTC 全年没跌 30%)⇒ 那三段是纯成本。
5. **把 funding 换成 `funding_7d_ann_binance`(表里有 2020-01-05 起的完整窗口,非空 2,495 天)也不翻转结论**:
   `n_components` 升到 8,但 turning 天数 222、段内占比仍 0、(b) 仍 0 段达标、Calmar 分位 0.556。
   ⇒ **❌ 不是"只差一个 funding"就能救回来的**。

## 7 · 探索性发现(需另立预注册、在新数据上过零信号对照)

- **2020 年在当前口径下永远不可能有相位**(365 天扩张窗口 + 数据从 2019 起)⇒ S-713 用「2020 起」做回放窗口对 ⓪ 不公平;
  若要继续,窗口应从 2021-01-24 之后(`funding_7d_ann_binance` 有 z 之后)起算,或在预注册里改成**滚动窗口 z**。
- **"段"这个单位有 60% 是擦边段**(30 段里 18 段 ≤ 3 天,中位 2 天)⇒ (a) 用"中位占比"会被它们压到 0;
  换成"总事件日占比"(68/696 = 9.8%)或"峰→谷口径"都救不了 —— 亮灯本身就不在段里。
- **turning 的 4 段区间里最长一段(134 天,2023-06-11→10-22)落在完全没有 ≥30% 回撤的时段** ⇒ 把 turning 当减仓信号,
  在那段时间里是纯成本(敞口减半而价格没跌)。
- **R 的总收益比持有高(+1006.8% vs +977.4%)但与随机择时分不开(67 分位)** ⇒ 又一次撞上「同平均仓位恒定持有 / 随机对照」这条纪律:
  少亏 3.6pp 的 MDD 不构成"⓪ 有用"的证据。
- `state_daily` 里同时存在 `funding_7d_ann` 与 `funding_7d_ann_binance`,**后者覆盖完整窗口** —— ⓪ 管道选了前者。
