## 🔴 最严重的一条:护城河概念正在生产环境上发出它支撑不了的断言

`/api/v1/cis/universe` 的每个资产都带 `cause_proximity`:

```json
{"out_of_circle_risk": "low", "risk_score": 0.201,
 "stage": null, "season": null, "days_since_chuquan": null,
 "drivers": ["consensus still upstream / in-circle — no out-of-circle stress detected"],
 "source": "market_proxy"}
```

实测 58 个资产:**`stage` 100% 为 null,`out_of_circle_risk` 100% 为 `low`。**

- `source: "market_proxy"` **是诚实的** ✓ —— 字段级别标注了它是代理
- **但那句 driver 不诚实**:「no out-of-circle stress detected」是**一个不存在的检测给出的否定结论**。
  它不是说「我们不知道」,是说「我们看过了,没事」。
- **一个 100% 输出同一个类的分类器,和一个被关掉的分类器,消费者无法区分。**
  这是 S-131 的 `cap_source`(存在、被展示、永远同一个值)——**长在护城河上。**

**为什么这条比之前所有同类都严重:**

1. 它在**护城河概念**上,不在管道上。ARCHITECTURE 第 154-156 行说我们的墙就是
   「出圈 stage、proximity-to-cause」这类**难算难验证的上游判断**。
2. 它以**自然语言**说给消费者听,而不是留在一个数字字段里。
3. ARCHITECTURE 第 164 行:
   > **「一个我们没有跑过自己回路的信号,是我们不得宣称的信号。
   > 宣称未经证明的东西是自欺,而自欺无法教人。」**

   **我们正在宣称它。在每一个资产上。此刻。**

**这是一个 P0,而且是按我们自己的教条判的 P0。** 修法不是把 `risk_score` 算出来
(那是研究项目),是**让缺席看起来像缺席**:`stage` 为 null 时,
`out_of_circle_risk` 必须是 `unknown` 而不是 `low`,driver 必须说
「未测量」而不是「未检测到压力」。
