# Jev 与决策内核:当 AI 不止说话

*CometCloud 研究笔记 · 2026-09-18 · 中文导读版*
Seth (Sabastian Bath) · Looloomi · CometCloud AI

## 一、开篇 · 一份工程事实清单(刘慈欣式)

**TypeSafe AI 在 2026 年 9 月 16 日发布了一个 AI 模型。它不会写文章,不会生成代码,不会解释自己。**

这不是产品修辞。它是接口定义。

按时间顺序排列的硬事实:

- 模型名称:**Jev**,由 ChatGPT 共同发明人 Diogo Almeida(RLHF 与 InstructGPT 共同作者)用 **RLCD(Reinforcement Learning from Calibrated Decisions)** 训练两年。
- 资金状态:隐身模式走出来,**$40M early-access 估值**。
- 架构性质:**非自回归、单次前向**;无 token-by-token 采样循环;输出层是一个结构化输出头,一次性吐出全部字段。
- 接口形态:三个原语——**Choice**(多选项 + 概率分布)、**Score**(有序等级 + 连续分数 + 置信度)、**Noul**(二元命题 + P(true))。三个原语可在同一次请求中并行评估。
- 延迟区间:**70–500 毫秒**,无论原语数量多少;最快的内部案例 114 毫秒。
- 价格:**输入 $0.042 / M tokens;输出 unmetered**。TypeSafe 自报比同尺寸前沿 LLM 快 20–200 倍、便宜 40–400 倍。
- 性能数字(自报):四个工作流平均**与前沿 LLM 标签一致率 67.8%**;最差工作流(invoice processing)与前沿相差 **17.3 个百分点**。
- 训练方法学公开状况:RLCD 的奖励函数、训练数据、模型规模、架构参数、独立复现——**均未公开**。
- 公开架构定位:**Kahneman "System 1" 工程对应物**——快、直觉、并行、不反思。

把它放在 2026 年的 AI 产品光谱里,Jev 占据一个此前空着的位置:它不是聊天模型碰巧输出 JSON,而是一个从设计层就把语言生成排除在外的判别器。它的全部存在,是为了回答"这个该归到哪一类?这是几分?这件事成立吗?"——并把答案连同置信度一起交回给代码。

把这十行读完,你已经知道了 Jev 是什么、不是什么、跑得多快、贵不贵、准不准、谁造的、缺什么公开材料。下面用一种更慢、更接地气的方式,把它放进一个具体生产 AI 系统里,告诉你"该不该用、怎么用、用在哪"。

## 二、展开 · Jev 在一个真实生产系统里放在哪里(齐锐式)

先说一个具体的场景。

假设你管着一个真实的交易系统——不是教学例子,是 CometCloud 自己跑的那一种。系统每天会产生几千条 trace、几百条 fill、几十条 sleeve 状态变化。每个 trace 都需要被"审一遍":这条 trace 是 noise 还是 incident?这条 fill 是不是符合 doctrine?这个 sleeve 状态变化是不是和 macro label 一致?

在 Jev 出现之前,你只有两个选项:

**选项 A:不用 AI 审,只用规则。** 阈值、关键词、长度——这些规则的好处是快、便宜、可解释;坏处是它"看不懂",任何超出规则模板的边角情况都会被误判或漏判。在生产里,这通常意味着你要么写几千条规则(每条规则都是债务),要么接受一个固定的低准确率天花板。

**选项 B:用 LLM 审,每次调一次 GPT。** GPT 看得懂,但每一次调用 300 毫秒、3 美分。几千条 trace 跑一遍,光延迟就 10 分钟,光成本就几十美元。在生产里,这意味着你**根本不会真的去审**——你只会在"出了事以后"才调一次 GPT 复盘。换句话说,大部分 trace 是"裸奔"的。

Jev 提供的是**选项 C:让 AI 真正去审每一个 trace、每一次 fill、每一个状态变化。**

这就是 Kahneman 区分 System 1 和 System 2 的现实意义。System 2(LLM、人类、复杂规则引擎)是慢的、贵的、可解释的——它适合做"我需要想清楚这件事"的工作。System 1(Jev)是快的、便宜的、不可解释的——它适合做"我需要立刻知道这看起来对不对"的工作。一份严肃的生产 AI 系统里,System 1 不是 System 2 的替代品,而是 System 2 的"周边神经"——它让 System 2 不必为每一件小事醒来。

具体到 CometCloud 这种系统的判断框架,看五条就够了:

| 信号 | 它意味着 |
|---|---|
| **判定**(Judgement) | 这件事需要语义理解,不是算术 |
| **有界**(Bounded) | 输出空间小且定义清晰(Choice 选项 ≤255、Score 等级 ≤10) |
| **原子**(Atomic) | 是一次判断,不是多步推理链 |
| **上下文闭合**(Context-contained) | 决策需要的所有信息都在这一次请求里 |
| **人类快答**(Fast-human) | 一个训练有素的人能在 5 秒内做出这个判断 |
| **机器消费**(Machine-consumed) *(极强信号)* | 消费这个判断的是代码,不是人 |

判据:**5–6 条打钩**——优秀的 Jev 候选;**3–4 条打钩**——拆解后部分用 Jev;**0–2 条打钩**——选别的技术。

把这个框架套到三个具体场景上:

- **场景 A · 合规预筛**:"这条文案里有没有出现 BUY/SELL 类的投顾语言?"——判定 ✓ / 有界 ✓ / 原子 ✓ / 上下文闭合 ✓ / 快答 ✓ / 机器消费 ✓。**6 分,优秀候选。**
- **场景 B · 日志分诊**:"这条 ops-console 行是真 incident 还是历史化石?"——判定 ✓ / 有界 ✓ / 原子 ✓ / 上下文闭合 ✓ / 快答 ✓ / 机器消费 ✓。**6 分,优秀候选。**
- **场景 C · 多步推理的投资决策**:"基于当前 macro、sleeve 状态、近期 trace,这个仓位调整的预期夏普是多少?"——判定 ✗(需要推理)/ 有界 ✗(输出空间大)/ 原子 ✗(多步)/ 上下文闭合 ✗(跨多源)/ 快答 ✗(人类需要几小时)/ 机器消费 ✗(人最终拍板)。**0 分,不要用 Jev。**

这个判据不评判 Jev 的好坏,只判断它和你的任务是否匹配。把"该不该用 Jev"这件事从争论变成清单,本身就是齐锐那一路"降维"思路的应用——把抽象的"AI 模型选型"翻译成工程师可以照着打钩的条目。

## 三、收束 · 五个冷静的批评

以下五项,任何一项单独存在都足以让 Jev 从某个具体工作流中出局。合在一起,它们界定了 Jev 当前的适用边界。

**批评一 · 精度差距不是噪声。** 在 TypeSafe 自己公开的四个工作流上,Jev 平均落后前沿 LLM 6 个百分点;最差的工作流落后 17.3 个百分点。跨工作流的方差(61.8% 到 76%)已经大到"Jev 已校准"不能替代"Jev 是对的"。任何一次高风险决策,前沿 LLM 期望会更高。

**批评二 · 校准是 population-level,不是 per-decision。** 一个模型可以**平均而言**校准得很好,但在任意一次具体决策上仍然自信地错。"Jev 67.8% 的概率选对"并不意味着"Jev 给出 0.83 的置信度就意味着这次 83% 会对"。每次决策的校准必须独立测量——TypeSafe 没有公开这部分。

**批评三 · 组合危害。** 一个工作流如果组合 12 次 Noul 调用,每次校准到 0.85,**不会**得到一个端到端校准到 0.85¹² ≈ 0.14 的决策。中间的阈值、权重、分支会以非显然的方式放大或摧毁校准。TypeSafe 的评估没有处理组合问题。对于任何聚合多次 Jev 调用的决策系统——这是绝大多数生产系统——这是未解决的问题。

**批评四 · 不透明。** 输出是一个概率,没有解释,无法申诉,无法调试。一个返回 `{doctrine_compliant: 0.18}` 的系统,无法告诉你**为什么**。对于受监管的工作流(金融、医疗、法律),这可能是取消资格的理由。对于内部 triage(路由、预筛、运维分类),这没问题。

**批评五 · 阈值耦合。** 如果你的路由策略是"Noul 返回 > 0.7 就升级",这个阈值是按 Jev 的分布校准的。模型升级导致分布漂移,你的升级率会静默变化。每次模型版本更新都必须重新调阈值。LLM 也有同样问题,但 LLM 更新频率低、漂移幅度小。

这五条不否定 Jev,它们**界定** Jev 的使用边界。

## 四、我们自己的判断

Jev 是 2026 年架构上最诚实的 AI 产品。它不假装自己是一个碰巧输出 JSON 的聊天模型。它是一个返回带校准概率的类型化判断的决策内核。在它被设计来做的任务上,它比前沿快 25 倍、便宜 76 倍。在同样的任务上,它也比前沿**少 6 个百分点的准确率**,并且尚未公开训练方法、尚未独立基准、尚未证明组合保证。

对于 CometCloud 的决策系统——**验证装置本身就是产品**的那一种系统——Jev 在场景 A 和场景 B 的位置上是合格的(替代廉价分类器、为每一个 trace 提供廉价验证),在场景 C 的位置上不合格(取代不了 auditable + composable + explainable 的内核)。

决策内核保持可审计、可组合、可解释。Jev 在边缘处赢得位置,在边缘处,它的替代品是"完全不判断"。

Kahneman 的框架终于变得可操作了。System 1 是真的。它快。它便宜。它也不那么准。我们应当知道何时使用它。
