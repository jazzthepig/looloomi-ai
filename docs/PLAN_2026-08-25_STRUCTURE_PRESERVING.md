## 2. 降维打击是什么(具体的,不是修辞)

不是"我们维度更高"。是:

> **我们能说出一个数字是怎么来的,以及它在哪一维上不成立 —— 而市场上绝大多数
> 研究产出说不出。**

M-83 是活的例子,而且是我们自己人做的:四个变体、11 个资产、73 天,
**报告里没有一处写价源**。那不是 C 的疏忽,那是这个行业的默认状态。
`assert_single_source()` 让"说不出价源"从一个习惯变成一个**抛异常的条件**。

三条可执行的差异化,全部来自今天已有的东西:

**① 每个数字带着它的出处与覆盖走。**
`SeriesSource` / `FetchCoverage` / `MarkResult` / `NavWrite` / `RebuildResult` ——
五个模块,同一个模式:**结果 = 值 + 它的可信域。** 别人给你一个 Sharpe;
我们给你一个 Sharpe、它的价源、它的覆盖窗口、以及它在多少个独立观测上成立。

**② 拒绝比结果更有信息。**
`BLOCKED ≠ FLAT`、`unreadable ≠ stale`、`UNMEASURABLE ≠ 0`。
一个说得出"我为什么算不了"的系统,比一个总能给出数字的系统**更值得接**。

**③ 折价是默认,不是选项。**
`deflated_sharpe` + `n_trials`。`experiment_runs` 60 条里 dsr 只有 2 条 ——
**这一条补完,我们就能说出"这几个月哪些结果是真的"**,而这是绝大多数
研究流水线永远给不出的答案,因为它们没记 `n_trials`。

## 4. 一条方法论,今天被撞出来的

三次连续撞击(S-231/232/233)之后才成形,不是想出来的:

> **先读消费者,再写生产者。**

要建一个日写者,连撞三个此前无人记录的约束:链是活的(RPC 在 Postgres 不在 Python)·
增量写在数学上不可能(z-score 跨全史)· `vec_full` 是位置数组不是字典。
**三个都只有在动手之前去读消费者才会发现,而三个都足以让写者静默产出错误结果。**

而它的反面今天也出现了 —— **我在写下这条的同一天,把一个有 8 个调用者的模块整份换掉**(S-236)。
所以这条不是训诫,是一个**必须被关卡执行**的东西:`test_research_imports` 就是它的执行形式。
