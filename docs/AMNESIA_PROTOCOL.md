## 3. 修复原则:传验证,不传记忆

传记忆会失败,因为记忆载体会膨胀、会过期、会被跳读。传验证不会,因为:

- **命令不腐烂。** `curl -s $SB/rest/v1/rpc/x -w '%{http_code}'` 今天和三个月后含义一致。
- **命令是自证的。** agent 不需要相信文档说"这个漏洞开着",它跑一次就看见真相。
- **命令能进 CI。** 一条能失败的检查,才是检查。

**⇒ 每一条 open risk 必须携带一条一行验证命令。没有验证命令的风险条目视为未记录。**

## 4. 冷启动契约(替代现有的"读两个文件")

### 4a. `PROJECT_STATE.md` 顶部必须是 `## OPEN RISKS`,在任何叙述之前

格式硬性规定 —— **每条 ≤3 行,必须含 `VERIFY:` 一行**:

```markdown
## OPEN RISKS  (≤7 条 · 冷启动第一屏 · 每条必须可验证)

1. **匿名远程写入 RPC 未封** — supabase_security_hardening.sql §1 未执行
   VERIFY: curl -s -o /dev/null -w '%{http_code}\n' -X POST -H "apikey: $ANON" \
     -H 'Content-Type: application/json' -d '{"p_symbol":"x","p_asset_class":"crypto","p_start_ms":1}' \
     "$SB/rest/v1/rpc/backfill_binance_ohlcv"     # 期望 401/403;若 200 ⇒ 仍开放
   OWNER: Jazz(Supabase 控制台)

2. **无外部告警** — 所有巡检跑在被监控的进程内;10.4h 无人发现会结构性复现
   VERIFY: 无。这条本身就是"没有验证手段"⇒ 优先级最高
   OWNER: Seth(待 Jazz 批准建定时任务)

3. **asset_embeddings 仍 72 行单快照** — 风格轮动无法回测
   VERIFY: select count(*), count(distinct symbol) from asset_embeddings;   # 期望 >>72
   OWNER: Minimax-A (M-WO-D1)
```

**上限 7 条是设计,不是偷懒。** 一份 30 条的风险清单和没有清单等价 —— 都不会被读完。
超过 7 条说明该收敛或该关掉一些,不是该加长。

### 4b. `MEMORY.md` 硬上限 4KB,由 CI 执行

现在 7.6KB。**规则早就写着 ≤4KB,只是没人执行 ⇒ 那不是规则,是愿望。**
只留"永不失效的事实"(本体、收益层级、不变量、协作规则)。
任何带日期的、会过期的东西不属于 MEMORY,属于 PROJECT_STATE 或台账。

### 4c. 台账只写不读 —— 必须接受这一点并据此设计

5,672 行的 append-only 台账**是正确的档案,不是可用的记忆**。
它的作用是"事后可审计",不是"冷启动可消费"。
**⇒ 任何进台账的教训,如果需要影响未来行为,必须同时落成一条可执行检查或一条 OPEN RISK。
只进台账 = 只留档,不改变行为。**

这条是本 session 三条教训的直接推论,也是它们能否活过下一次失忆的唯一分野。

### 4d. `MINIMAX_SYNC.md` 需要一个"当前状态"头部

只增不改保证了历史完整,但让有效记忆退化成"最后几屏"。
**顶部加一个可覆写的 `## NOW` 区块**(≤20 行:各 lane 状态、待 ack、阻塞项),
历史继续在下面 append。**append-only 适用于证据,不适用于状态。**

## 5. 用可执行检查关掉的掉点(在 preflight 里)

| 掉点 | 检查 | 状态 |
|---|---|---|
| MEMORY.md 膨胀 | `wc -c MEMORY.md` ≤ 4096 | 待建 |
| PROJECT_STATE 头部过期 | 头部日期 < 台账最新条目日期 ⇒ 红 | 待建 |
| OPEN RISKS 缺失或缺 VERIFY 行 | 解析顶部区块,每条必须含 `VERIFY:` | 待建 |
| DB 侧超时被改回 | `pg_roles.rolconfig` 缺 `statement_timeout` / `idle_in_transaction_session_timeout` ⇒ 红 | 待建 |
| 策略模块未声明 DECISION_INPUTS | ✅ 已建(真扫描 + 欠账表) | 已上线 |
| 只报聚合指标 | ✅ 已建 | 已上线 |
| 风控切断后无恢复路径 | ✅ 已建(breaker cooldown + 锁释放) | 已上线 |

**前四条正是"守卫不观测真实制品"的剩余化身。**

## 6. 一条给撞上基础设施故障的 agent 的硬规则

S-83 的绕行代价被精确量化成了 **10.4 小时宕机**。所以:

> **撞上基础设施故障时,绕行是允许的 —— 但必须同时在 `PROJECT_STATE` 的 OPEN RISKS
> 里留下一条带 `VERIFY:` 的条目。绕行不留痕 = 把故障传给下一个失忆的自己。**

绕过去继续跑通常是对的工程判断(当时要的是曲线,不是完美的基础设施)。
**错的不是绕行,是绕行之后没有留下任何东西让下一个人看见。**

## 7. 诚实的边界

- 本文档**本身**也会被跳读。它的价值不在于被通读,而在于 **§4a 的 OPEN RISKS 格式
  和 §5 的 CI 检查** —— 那两样不需要任何人读这份文档就会生效。
- **§4a 上限 7 条会带来"该丢哪一条"的判断压力。** 这是有意的:
  逼迫收敛好过维护一份没人读的长清单。
- 本文档无法修复的:**agent 在诊断中过早下结论**(本 session 我从一句横幅跳到数据量结论)。
  目前唯一的缓解是"下结论前先做一个对照实验",而这条**只是纪律,没有可执行检查**。
