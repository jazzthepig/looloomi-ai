## 2. 最值得拆的一个:Numerai 的 MMC

### 2.1 它是什么

2024 起 Numerai 主赛的支付**只按 MMC(Meta Model Contribution)**:
**你被支付的不是「你对不对」,而是「你相对于已有共识增加了什么」。**
如果你的模型只是复述大家都在预测的东西,**你赚不到钱**。

配合质押:提交要押 NMR,**分数为正得付款,为负则销毁**,单轮上下限 ±5%。
「skin in the game 让 Numerai 可以信任提交的质量,否则任何人都可以交垃圾而不受惩罚。」

### 2.2 为什么这是 Berk–Green 的实际解法(我认为这是本文最重要的一点)

Berk–Green:**按历史 % 业绩选人,均衡中得零。**
Numerai 的回答不是「更好地选人」,而是**换支付对象**:

> **不为业绩付费,为正交性付费。**

**正交性不会被资金流以同样方式竞争掉** —— 它是关于**组合的相关结构**,
不是关于个体的 alpha。一个新来的贡献者只要与现有共识不同,就有价值,
**哪怕他的绝对业绩不如现有成员。**

### 2.3 我们已经有算它的机器,而且我们比大多数人更需要它

- 实测 **N_eff = 3.1**(75 资产,ρ̄ 0.310)—— 我们的问题恰恰是「什么都相关」
- `strategy_embedder` 里已有 `redundancy()` / `coverage_gaps()`
- `docs/VDB_DIRECTION` 已把 VDB 定位为「策略嵌入 + 反证检索」

**⇒ MMC 是「N_eff 太低」这个病的机制设计版本,而我们有向量基底可以直接算。**
**这是四个象限里唯一一个「我们不缺零件,只缺组装」的。**

## 3. 比我们强的,以及强在哪(不粉饰)

### 3.1 Almanak —— 强在钱和托管,而且差距是数量级

- **TVL 峰值 $132M · 10 万用户 · 年化收入约 $600 万**(2025-12)
- 18 个 agent 组成的 swarm:研究 → 模拟 → 部署 → 风控
- **TEE + 多签金库** —— 把「我凭什么把钱交给一个 agent」这个问题用**硬件信任**回答了
- 已发币(2025-12-11,Bybit / Kraken / Gate / MEXC)

**对照我们:干净前向记录 0 天,收入 0。**
**这不是"我们方向不同"能解释掉的 —— 他们在做同一件事并且已经在收钱。**

**能拆的:** 托管答案。我们讲 FoF、讲机构,却没有回答「资金放在哪、谁能动」。
**Almanak 用 TEE 回答了。这是我们对 LP 与对 agent 都必须回答的问题,而我们还没有答案。**

### 3.2 Numerai —— 强在机制设计的深度

我们的 SHIP 门槛是**规则**(cause / OOS / 60 天 / DSR / PBO)。
Numerai 的是**激励**(押注、销毁、按正交性付费)。
**规则要靠人去执行,激励自己执行。**

**我们没有 skin in the game。** 我们的台账是自己写给自己的。
Numerai 的 3 万人是因为**赔钱**才不交垃圾。

### 3.3 Enzyme / dHEDGE —— 强在验证是构造性的

链上每笔交易可审计,**记录无法伪造**,不需要任何人信任任何人。
我们的前向记录是**我们自己往 Supabase 写的行** ——
今天一整天证明了它可以被写错、被静默丢失、被作废重来。

**⇒ 一个诚实的 LP 会问:「你们的记录凭什么可信?」**
**目前的答案是「我们很自律」。那不是一个可承销的答案。**

---

## 4. 但有一个反向证据,必须一起看

**dHEDGE TVL 只有 $12.2M。**

链上、完全可验证、无需信任 —— **而它没有募到钱。**

**⇒ 可验证性不自动带来资金。**
这直接约束了我们「验证装置就是产品」这个主张:
**装置是必要条件,不是充分条件。** 分发、托管、准入、关系,才是把它变成钱的东西。

**这一条应该写进对外材料的自我批评里,而不是被回避。**

---

## 5. 我们真正可能独有的(以及为什么它可能不值钱)

**没有一家在做机制层面的证伪台账。**
Numerai 验证**业绩**;Enzyme 验证**执行**;
**我们验证的是推理 —— 110+ 条写明「为什么错」的记录,编译进 CI。**

**但要诚实:没人做,可能是因为不值钱。**
判据只有一个 —— **有没有人愿意为它付费,或因为它而把钱交给我们。**
在有第一个付费方之前,它是一个假设,不是护城河。

**可检验的最小版本:** 把台账做成可查询的 A2A 接口,
让别的 agent 问「这个想法被否过吗、什么机制」。
**如果有 agent 来查、且愿意付费 —— 那才是证据。**

---

## 6. 我建议按这个顺序拆(按「能不能立刻做」排,不按宏大程度)

| # | 动作 | 依据 | 我们缺什么 |
|---|---|---|---|
| 1 | **把 MMC 逻辑接进策略评估** —— 不按绝对业绩排序,按对现有组合的正交贡献排序 | Numerai + Berk–Green | 只缺组装,零件都有 |
| 2 | **回答托管问题** —— 资金放哪、谁能动、怎么证明 | Almanak TEE | 完全空白 |
| 3 | **让记录不可伪造** —— 至少把 NAV 逐日哈希上链或第三方公证 | Enzyme 构造性验证 | 完全空白 |
| 4 | **台账 A2A 接口 + 找第一个付费查询方** | 我们独有,但未经检验 | 需求侧验证 |

**1 是唯一今天就能开始的。2 和 3 是「可承销」的前提,不是加分项。**
