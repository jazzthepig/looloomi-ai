## 4. S-123:今天挖到的复合 bug(为什么时钟是脏的)

三个独立 bug 叠在同一个 40 行函数里,任何一个单独出现都不致命:

```
① _regime_history() 查询 order=recorded_at.asc & limit=20000
   窗口内实际 53,250 行 ⇒ 上限截掉的是【最新】那一端
   ⇒ 书能看到的最新日期 = 2026-07-17,而今天是 2026-08-09(陈旧 23 天)

② 陈旧序列 + Redis blob 缺字段 → canonical_regime(None) = "NEUTRAL"(宽松版)
   ⇒ 昨天修了 cis.py 的两个调用点,但【这个模块有自己的调用】

③ _exposure_cap("NEUTRAL") = 1.0 而 TIGHTENING = 0.5
   ⇒ 书以两倍于应有的暴露记录了它全部的前向记录
```

**`limit` + 升序 = 静默的「最旧 N 条」,而被丢掉的恰好是唯一有用的那一端。**
更阴险的是:**陈旧序列和新鲜序列长得一模一样** —— 一样的长度、一样的标签,
只有覆盖的日期不同,下游无法分辨。⇒ 序列必须**自证抵达当下**,不能被信任。

已修 + 已守卫(`test_regime_write_path` 8/8),并顺带修掉另外 4 个模块里同样调用
宽松版的写入路径 —— 其中 `main.py` 写的正是 ① book 要读的那张表,**闭环**。
