# QA Report — Main App Dashboard (looloomi.ai/app)

**Date:** 2026-06-05 · **Lens:** trader-agent / developer · **Method:** live walkthrough
of every dashboard route + network/console capture on production.

## Summary

The **design layer is institutional-grade; the data layer at the edges is not.**
The single biggest issue is a **CIS universe data outage** that cascades into every
surface that consumes scores (homepage widget, CIS Leaderboard, Asset Radar,
Portfolio). Underneath it is a **systemic frontend duplicate-fetch storm** that trips
the rate limiter and produces self-inflicted 503s. Separately, the public **Signal
Performance** page shows mathematically broken and reputationally damaging numbers.

Routes that work well: Protocol Intelligence, Sector Heatmap, Macro Events, VC, Vault.

---

## P0 — CIS universe data outage (flagship feature down)

`GET /api/v1/cis/universe` returns **HTTP 200 with `universe: []` (0 assets)** —
verified 5× from the page context — and intermittently **503**. Populated data was
present ~20 min earlier (MANTLE etc.), so the Mac Mini push went stale (2h Redis TTL
expired) and **the Railway T2 fallback is not engaging when the cache is empty**.

Cascade (all same root cause):

| Surface | Symptom |
|---|---|
| Intelligence homepage | CIS widget "0 assets", regime "Unknown", FED/10Y/VIX/DXY/CPI all `—` |
| CIS Engine → Leaderboard | "Failed to load: No data returned" + Retry |
| CIS Engine → Asset Radar | Prices load, but **CIS / LAS / SIGNAL columns all `—`** for every asset |
| Portfolio | Stuck on "Loading CIS universe… Live prices will appear shortly" — can't add assets |

**Root cause:** (1) Mac Mini `cis_scheduler.py` push may be stale/stopped; (2) the
universe endpoint returns empty instead of degrading to the Railway T2 "ESTIMATED"
estimation path. CLAUDE.md design rule #5 ("skeleton loaders only, never empty
states") and the documented amber "CIS MARKET · ESTIMATED" fallback are both being
violated.

**Fix (Seth):** make `/api/v1/cis/universe` never return empty — when Redis cache is
empty/stale, compute T2 estimation inline so the leaderboard always has data.
**Investigate (Minimax):** confirm `cis_scheduler.py` is alive and pushing (build-state
`last_cis_push.stale` will show this once deployed).

## P1 — Frontend duplicate-fetch storm → self-inflicted 503s

A single dashboard load fires the same endpoints repeatedly:

| Endpoint | Calls / load | 503s |
|---|---|---|
| `/api/v1/cis/universe` | **7** | 1 |
| `/api/v1/defi/overview` | 3 | 1 |
| `/api/v1/intelligence/macro-events` | 3 | 1 |
| `/api/v1/protocols/universe` | 3 | 1 |
| `/api/v1/macro/brief`, `/economic-indicators`, `/vc/portfolios`, `/vc/funding-rounds` | 2 each | — |

Multiple components fetch the same endpoint independently; the burst trips the
rate-limit middleware, returning 503, and the component that lost renders empty. This
is the proximate cause of the empty CIS widget on the homepage.

**Fix (Seth):** dedupe to a single shared fetch per endpoint (lift to a parent/context
or a small request cache / React Query). Optionally relax the rate limiter for
same-origin GETs.

## P1 — Signal Performance: broken math + damaging public exposure

Trading Engine → Signal Performance (badged **LIVE**) shows:

> Sharpe **−24.51** · Sortino **−13.49** · Max Drawdown **−85.11%** · Win Rate **0.0%**
> · Profit Factor **0.00** · Avg Return **−14.20%** · Portfolio **$100k → $14.9k** · 15/16 closed

Two distinct problems:
1. **Math bug.** Sharpe of −24.5 is not physically meaningful. `_compute_metrics()` in
   `signals.py` annualizes per-signal returns with `sqrt(min(N,252))`, which explodes
   the ratio. Treating each discrete signal as a daily period is wrong.
2. **Methodology + exposure.** The 16 closed signals all come from the **downgrade-close
   path** — winners stay open, losers close → **0% win rate by selection bias**. This is
   exactly what the new 30-day fixed-horizon outcome tracker corrects, but those
   outcomes don't resolve until ~June 24. Showing −85% / $14.9k publicly under a LIVE
   badge actively contradicts the alpha narrative.

**Fix (Seth):** correct the Sharpe/Sortino formula; gate or relabel this page as
"building — first 30-day outcomes resolve late June" until the outcome tracker has a
real sample. Do not present downgrade-close equity as a live track record.

## P3 — Low-contrast micro-labels

Section sublabels (`SIGNALS · EVENTS · MACRO`), column headers, and stat captions are
very low-contrast grey on void-black — hard to scan quickly, which matters most for
the dense-data trader lens. Bump label contrast one step (keep the void-black aesthetic).

## Fixes applied this session (backend — Seth, pending deploy)

- **P0 never-empty universe** — `/internal/cis-scores` now writes a 7-day
  `cis:last_known_good` snapshot on every push; `/api/v1/cis/universe` serves it
  as a final `degraded`/`source:last_known_good` floor before ever returning `[]`.
  The leaderboard can no longer go blank when the Mac Mini push stalls.
- **P1 503 burst** — `/api/v1/cis/universe` now has a 30s response cache +
  `asyncio` single-flight, so the homepage's ~7 concurrent fetches collapse into
  one computation instead of overwhelming the worker.
- **P1 Signal Performance math** — removed the broken `sqrt(252)`/empyrical
  annualization; Sharpe/Sortino are now sane per-trade ratios (−1.05, not −24.5).
  Added a `methodology` block to `/api/v1/signals/performance` flagging the
  closed-signal sample as downgrade-close (selection-biased) with the 30-day
  outcome as the forward metric (first resolves ~2026-06-24) — frontend should
  use this to relabel/gate the LIVE badge.

- **P0 ROOT CAUSE FIXED** — the T2 `calculate_cis_universe()` was raising
  `UnboundLocalError` on *every* call: a stray `_fetch_narrative_signals() if not
  is_tradfi else asyncio.sleep(0)` inside the top-level `asyncio.gather` referenced
  a per-asset loop-local (`is_tradfi`) before assignment, which Python scopes as a
  local for the whole function. So the entire Railway T2 universe died instantly and
  the leaderboard went blank whenever the Mac Mini hot cache lapsed (data sources
  were all healthy — confirmed via debug endpoint). Replaced with an unconditional
  `_fetch_narrative_signals()`. Verified: T2 now returns `status: success` with
  scored assets (BTC/ETH graded B). The LKG floor + single-flight remain as defense
  in depth.
